# 本番ラン前 整合チェックリスト

> 2026-04-30 ステージ F-1。重い本番ランを **議事録ベースだと未着手のまま** 走らせて約 4 時間を無駄にした事故([問題点リスト §2-A](../../docs/03_ToDo/2026-04-30_問題点リスト.md))の再発防止。
>
> Claude(私)が `python -m src.main` のような重いランを起動する前に、**必ずこのチェックリストを通す**。

## 適用対象

以下のいずれかに当てはまるラン:

- `agents.num_agents >= 10`(大集団)
- `simulation.duration >= 30`(長 step)
- 1 ランあたり **15 分以上** の見積もり
- 4 シナリオ以上の連続実行
- 提出物 PDF の元になる本番ラン
- ユーザが「本番ラン」「prod_*」を指示している

軽量な検証ラン(5 体 × 5 step、`output/echo_check_*` 等)は対象外。

## チェック項目

### 1. 議事録の確認(最重要)

```bash
# 直近 24 時間以内のミーティング議事録があるか
ls -lt docs/02_ミーティング/*/02_議事録/*.md | head -3
```

- [ ] **直近 24 時間以内に新しい議事録があるか**を確認した
- [ ] 議事録に **比較軸 / モデル / 集団サイズ / シナリオ / ペルソナ** の決定事項があるか目を通した
- [ ] 議事録の決定が **要件定義書 / 機能要件 / システム設計** に反映されているか整合性を確認した

> 議事録 → 要件定義 → 設計 → 実装の流れが逆転していないことを確認する。
> 反映されていなければ **本番ランを開始しない**。先に要件定義の更新が必要。

### 2. 設定の整合確認

走らせるシナリオ yaml と base.yaml の最終 deep_merge 結果について:

- [ ] `llm.model` が議事録で指定されたモデル(タグ違いに注意)
- [ ] `agents.num_agents` が議事録で確定した値(最近の Singulab だと 5 / 100)
- [ ] `agents.persona` が新スキーマ(`age` / `gender` / `nationality` / `mbti`)。旧スキーマ(`role_distribution` 等)があれば legacy ディレクトリ確認
- [ ] `events:` セクション(または `fires:`)で観察したいイベントが正しく設定されている
- [ ] `simulation.duration` が議事録で承認された値

### 3. エコー対策の継承確認(2026-04-30 以降必須)

- [ ] base.yaml の `llm.max_tokens` が **100 前後**(極端に大きな値で長文を要求していない)
- [ ] base.yaml の `llm.temperature` が **0.7〜0.9**(0.5 以下で多様性を奪っていない)
- [ ] `_build_messages_context` が直近 1 件のみ + 引用形式(M-08 適用)
- [ ] `_build_persona_section` に `=== LANGUAGE REQUIREMENT ===`(M-06、日本語シナリオの場合)

### 4. 出力ディレクトリの衝突確認

- [ ] `--output-dir` で指定するパスが既存 run と被っていない
- [ ] 既存 run を上書きする意図なら明示的に `Remove-Item` で削除

### 5. ユーザ承認(以下のいずれかに該当する場合は必須)

- [ ] LLM モデルを **走行中に切り替える** ような対応(独断不可、議事録 §6-B)
- [ ] 集団サイズを大きく変える(5 → 50、10 → 100 等)
- [ ] 既存の `output/prod_*` を上書きする
- [ ] 1 時間以上かかる見込みの逐次ラン
- [ ] 粉川氏マシン側で実行すべきラン(34B × 100 体)を私側で代替実行しようとしている

## 使い方

ユーザから「本番ランしてください」「scenario_*.yaml で 100 step 回してください」のような指示が来たら、**Bash で `src.main` を起動する前に** このスキルを起動する。

実装(運用):

1. `Read` で `docs/02_ミーティング/` 直下の最新議事録を確認
2. `Grep` で対象シナリオが議事録の決定と矛盾していないかチェック
3. 上記チェックリストの 5 セクションを順に確認
4. すべて OK なら本番ラン開始
5. 1 つでも NG / 不明なものがあれば、**ユーザに確認を取る**まで待機

## 完了判定

- [ ] チェック 1〜4 すべて OK
- [ ] チェック 5(ユーザ承認)に該当する項目があればユーザの明示的な OK が出ている
- [ ] このチェックリストを通した記録(口頭で「議事録は最新 / 整合 OK」と報告)
