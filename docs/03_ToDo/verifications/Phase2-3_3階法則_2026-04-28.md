## 3. 統合スモークテスト

### 3.1 シナリオ([config/scenario_phase2_cognition.yaml](../../../config/scenario_phase2_cognition.yaml))

```yaml
world_laws:
  communication_radius: 5.0
  communication_radius_overrides:
    main_office: 30.0  # main_office 内は全員届く
  cognitive_limit: 2  # 4 体中 2 人しか覚えていられない
  message_delay: {same_place_near: 0, same_place_far: 1, cross_place: 3}
```

- 4 体 × 4 ステップ
- 全員 `main_office` 内、`comm_radius_overrides=30` で全員に届く
- K=2 設定 → 全員と話す中で頻繁に「忘却 + 再認識」が発生する想定

## 5. 注記

### 5.1 Agent.received_messages との重複

参考実装由来の `Agent.received_messages`(全件 FIFO)を Phase 1 互換のため残してある。新たに `Agent.cognitive_memory: AgentMemory`(他者ごと LRU)を追加した形。

- `received_messages`: プロンプトに渡す直近メッセージバッファ
- `cognitive_memory`: 「誰を覚えているか」の知人録

両者は別関心事なので二重持ちは設計上 OK。Phase 3 の `agent/memory.py` 分離で整理予定。

### 5.2 Phase 1 互換性

`world_laws` セクションが config に無い場合、`agents.communication_radius` を `WorldLaws.communication_radius` に流し込む後方互換ロジックを Simulation に追加した。これにより既存シナリオ(`scenario_bar_fire.yaml` 等)はそのまま動作。

### 5.3 message_delay の値だけ保持

`MessageDelay` の値は WorldLaws と run_metadata.json に保持されているが、現時点では **配送キューが未実装** なので動作には影響しない。Phase 3 で `DeliveryQueue` を追加するときに既存の値を読むだけで済むよう設計してある。
