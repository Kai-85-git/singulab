## 4. 観察と注記

- **`huihui_ai` シリーズの命名揺れ**: `qwen3-abliterated` / `dolphin3-abliterated` は `d` 末尾、`llama3.2-abliterate` は `d` なし。提供者(`huihui_ai`)が一貫していないため、新モデル追加時は必ず `ollama pull` で実機確認することを運用ルールに追加すべき。
- 8B の Dolphin が一番時間を要した(2:21 / 4.9 GB)が、6 GB VRAM 制約下で CPU オフロード併用前提のため pull 自体は完了。実推論は C-06(初回ヘルスチェック)で確認。
- **初回 pull 履歴は残す**:設計書を信じて pull → 失敗 → タグ修正 → 成功、という流れは将来同様の問題が起きたときの良い参照になる。
