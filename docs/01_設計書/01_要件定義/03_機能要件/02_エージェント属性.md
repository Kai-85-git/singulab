# 02_エージェント属性

> 2026-04-29 議事録 §4 で大幅改訂。**役割系の属性をすべて削除し、性格次元(MBTI)を導入**した。
> 2026-05-01 追補。エコーループ対策(問題解決ToDo §3)として **personal_context(生活の文脈)** を導入し、シナリオ単位で各エージェントに固有の個別性を付与する。

## 1. 採用する変数

| 変数 | 設定 | 補足 |
| --- | --- | --- |
| **年齢** | あり | 数値で付与 |
| **性別** | あり(男 / 女) | LLM はジェンダーレス概念を扱えない可能性が高いため生物学的のみ |
| **国籍** | **日本人ベース(90%)+ 外国人(10%)** | 4/24 議事録 §62「10 人中 1 人外国人」設計に回帰(2026-05-01)。「日本語で回答」は制約として固定 |
| **MBTI** | **あり ⭐** | 16 タイプから選定。役職/職業の代わりとなる性格次元 |
| **personal_context** ⭐ | **あり(2026-05-01 追加)** | 家族構成・趣味・今日の気分・最近気にしていること・何となく詳しい分野。**役職を直書きせず、生活の文脈で個別性を作る**(下記 §6) |

## 2. あえて入れない変数

- **役職 / 職種 / ロール**: 自然発生を観察するため意図的に未設定
- **男女比の固定**: 8:2 のような比率も外し、ランダムまたは試験条件で振る
- **出身地 / 学校 / 偏差値 等**: バイアスが強く創発を制約する懸念
- **均等な国籍ランダム配分**: 4/29 議事録で一度「均等ランダム」に変更したが、2026-05-01 にユーザ判断で 4/24 議事録の「日本人 90% / 外国人 10%」設計に**回帰**。日本のオフィスを舞台とするシナリオのリアリティを優先し、外国人比率を創発観察の閾値として保持するため

## 3. MBTI 採用の経緯

- タコさん(元・人材育成業)は「ロールを与えたい」バイアスがあると自己認識
- 粉川氏(元・製造業)は「役割で考える思考」を破壊したい意向
- 双方が「役割ベースを脱したい」点で一致 → **MBTI に着地**(指数が少なく、旬で、役割ではない性格次元)
- 個別ロール(エンジニア/PM 等)は **LLM 自身に内部で割り振らせる** 前提

## 4. システムプロンプト雛形(1 エージェントあたり)

```
私は{年齢}代の{性別}です。
国籍: {日本 90% / 外国 10%(8 ヵ国に均等配分)}
MBTI: {16タイプから選定}
日本語で回答してください。
```

## 5. 設計ポリシー(兵頭氏アドバイス準拠)

- **指示を書きすぎない**。プロンプトで命令するほど創発が死ぬ
- 役職・階層は「勝手に役割が決まっていく」様を観察したいのであえて定義しない
- LLM の国籍差(モデルが学習した国による性格差)も観察対象として扱う
- 「考えすぎない、感覚で投げ込む」方が創発が出やすい(2026-04-29 議事録 §3.4)

## 6. personal_context(2026-05-01 追加)

### 6.1 導入の背景

`output/prod_v2_alien_5`(Qwen3 4B, 5 体)後半で全エージェントが同一文を循環させる **エコーループ** を観測。原因の本質は「全員が同じインプット(同じイベント文 + 似た MBTI 行)を見ているため、似た出力が返る」こと。一度はプロンプトで「コピー禁止」と多様性を強制する案を検討したが、兵頭氏アドバイス「指示を書きすぎない」と反するため**撤回**。

代わりに、**インプット側を多様化**する方針として personal_context を導入する。各エージェントが固有の生活背景を持つことで、同じイベントへの反応が自然に分岐することを狙う。

### 6.2 スキーマ(任意・自由記述)

| キー | 内容 | 例 |
| --- | --- | --- |
| `family` | 家族構成・住まい | 「都内で一人暮らし。実家は地方」 |
| `hobby` | 趣味 | 「週末は街歩きでカメラを持ち歩く」 |
| `today_mood` | 今日の気分・体調 | 「風邪気味で少し集中力が落ちている」 |
| `recent_concern` | 最近気にしていること | 「親の体調と通院の付き添い」 |
| `expertise_hint` | 何となく詳しい分野(役職ではなく経験ベース) | 「学生時代に天文同好会で星を見ていた」 |
| `note` | 自由欄 | — |

すべて任意。空欄でもよい。**役職名(エンジニア/PM 等)、speaking_style、責務記述は入れない**(役割を演じさせる設計に戻ってしまうため)。

### 6.3 YAML 例

```yaml
agents:
  num_agents: 5
  personal_contexts:
    - family: "都内で一人暮らし。実家は地方"
      hobby: "週末は街歩きでカメラを持ち歩く"
      today_mood: "昨夜よく眠れた。少し雑談したい気分"
      recent_concern: "来月の引っ越し先がまだ決まっていない"
      expertise_hint: "学生時代に天文同好会で星を見ていた"
    # ... num_agents 件分
```

### 6.4 設計ポリシー(personal_context 固有)

- **状態記述として与える**。命令文(「〜してください」)は付けない
- LLM がこの個別性をどう会話に滲ませるかは観察対象。「天文好きの人が UFO に強く反応する」ような分岐が出ることを期待
- `personal_contexts` の長さは `num_agents` と一致させる。不足時はエラー
- 旧 `conversation_profiles`(role / speaking_style 直書き)は **legacy 扱い**。新規シナリオでは使わない。両方指定された場合は `personal_contexts` を優先し、警告ログを出す

### 6.5 段 3: イベント観察の非対称化(2026-05-01 実装)

段 2(personal_context)単体では `output/seg2_check_alien_5` 後半で再びエコーループが発生した(step 28 以降「UFO の形状変化の原因について…」が循環)。原因は **AlienEvent の prompt_text が全エージェントに同じ文を一斉注入する設計** だったため、後半の memory が同じ語彙で埋まり個性が薄れること。

#### 6.5.1 設計

`AlienEvent.perceived_info(agent_position)` を **距離依存** に変更。FireEvent と同じく、エージェントの位置と UFO 位置のユークリッド距離で 3 帯に分ける:

| 距離帯 | 既定閾値 | 知覚内容 | 例 |
| --- | --- | --- | --- |
| **Near** | 距離 ≤ `near_radius` (既定 8.0) | 詳細視認 | 「目の前に UFO がいる。座標 (-15, 12) でほぼ静止して見える」 |
| **Mid** | `near_radius` < 距離 ≤ `visible_radius` (既定 18.0) | 遠望 | 「遠くに UFO らしきものが見える。座標 (-15, 12) 付近」 |
| **Far** | 距離 > `visible_radius` | **直接観察不可** | `perceived_info` は `None` を返す。会話伝播経由でのみ知る |

#### 6.5.2 期待される効果

- 「先に見た人」と「後から会話で聞いた人」の発話が分離 → 自然な情報伝播・噂・誤解の観察が可能に
- 同一語彙の循環(エコー)が緩和される(全員のインプット冒頭が異なるため)
- 兵頭氏アドバイス「指示を書きすぎない」を破らない(状態記述だけで命令文は付けない)

#### 6.5.3 yaml 設定例

```yaml
events:
  - type: "alien"
    start_step: 15
    center_x: -15
    center_y: 12
    near_radius: 8.0      # 任意・省略時は 8.0
    visible_radius: 18.0  # 任意・省略時は 18.0
    move_step_size: 2
```
