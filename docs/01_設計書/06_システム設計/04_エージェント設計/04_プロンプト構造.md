# 04_プロンプト構造

## 1. Message プロンプト(Phase 1)

位置情報は含めない(参考実装踏襲)。

```
You are Agent {id} ({persona_summary}) in {world_description}.

=== YOUR CURRENT STATE ===
{persona_lines}
In place: {Yes/No}
{Current place line if in_place}
{Place status block — only if in_place}
{Environment readings block — only if env_readings is non-empty}
{Event section — only if event_infos is non-empty}

=== NEARBY AGENTS (you can communicate with these agents) ===
{nearby_text_without_position}

=== PREVIOUS MEMORY ===
{recent_memory}

=== MESSAGES FROM OTHERS ===
{recent_received_messages — 直近 1 件のみ。引用枠 + 「自分の言葉で返してください」}

=== あなたへ / YOUR TURN ===
{event-aware task block}

=== RESPOND IN JSON ===
{
    "message": "...(max 200 words, optional)",
    "reasoning": "brief explanation"
}

Step: {step}
```

## 2. Action プロンプト(Phase 3)

位置情報と、自分が Phase 2 で送ったメッセージを含める(参考実装踏襲)。

```
You are Agent {id} ({persona_summary}) in {world_description}.

=== YOUR CURRENT STATE ===
{persona_lines}
Position: ({x}, {y})
In place: {Yes/No}
{Current place line if in_place}
{Place status block — only if in_place}
{Environment readings block — only if env_readings is non-empty}
{Event section — only if event_infos is non-empty}

=== PLACE LOCATIONS ===
{all place locations}

=== NEARBY AGENTS ===
{nearby_text_with_position}

=== PREVIOUS MEMORY ===
{recent_memory}

=== MESSAGES FROM OTHERS ===
{recent_received_messages}

=== MESSAGE YOU DECIDED TO SEND ===
{message_to_send — if non-empty}

=== AVAILABLE ACTIONS ===
- "stay": remain at current position
- "move" with direction: "up" (Y+1), "down" (Y-1), "left" (X-1), "right" (X+1)

Field boundaries: X and Y from -{half_space_size} to +{half_space_size}

=== RESPOND IN JSON ===
{
    "action": "move" or "stay",
    "direction": "up" | "down" | "left" | "right" (only if move),
    "memory": "what to remember for next step",
    "reasoning": "brief explanation"
}

Step: {step}
```

## 3. セクション生成ルール

| セクション | 表示条件 | 内容(定量のみ) |
| --- | --- | --- |
| Place status | `in_place == True` | `Number of agents here / Capacity / Occupancy rate` |
| Environment readings | `env_readings` が非空 | `{field.name}: {value} ({unit})` |
| Event | `event_infos` が非空 | `Event "{name}": position/intensity/radius/your distance` |

**定性語の禁止**: 「危険」「安全」「快適」「混雑」等は使わない。LLM の解釈に任せる。

## 4. 多様性の出し方(2026-05-01 方針確定)

### 4.1 背景

`output/prod_v2_alien_5`(Qwen3 4B abliterated, 5 体, 30 step)後半で全エージェントが同一文を循環させる **エコーループ** を観測。一度はプロンプトで「コピー禁止」「自己発話と被るな」と**多様性を強制**する案(A+B)を入れたが、これは兵頭氏アドバイス「指示を書きすぎない」と反する=創発の本質ではないため**撤回**(2026-05-01)。

### 4.2 採用方針: インプット側の多様化で自然分岐させる

プロンプトで縛るのではなく、各エージェントの**インプット自体を多様化**し、自然に異なる発話が出るようにする。

| 軸 | 方策 | 状態 |
| --- | --- | --- |
| **エージェント個別性** | `personal_context`(生活の文脈)を 1 段落付与。家族・趣味・今日の気分・持っている知識など。MBTI とは別軸の個別性を作る | ✅ **段 2 実装済**(全本番ラン適用) |
| **観察情報の非対称化** | `AlienEvent.perceived_info` を位置依存に。near/visible/far 帯で切り替え | ✅ **段 3 実装済**(`prod_v3_alien_5` / `prod_v3_alien_100_v2`) |
| **モデル容量** | 4B は MBTI/personal_context の差を表現しきれない可能性。**34B での 100 体ラン**で再走させる比較は今後の課題 | 段 4(7 章「未解決課題」§7.8) |

### 4.3 4B での検証規模(本提出物の実績)

Kai 側 PC(RTX 3060 Laptop 6GB / Ryzen 7 6800H)で Qwen3 4B abliterated を Ollama 並列で実行した実測:

| 用途 | 規模 | 実測時間 |
| --- | --- | --- |
| 機能検証(personal_context が動くか) | 5 体 × 30 step | 約 30 分(`prod_v3_alien_5`) |
| 本番創発観察(コア観察軸) | 100 体 × 30 step | **約 8 時間 31 分**(`prod_v3_alien_100_v2`) |
| 100 step 化 / 34B での再走 | — | 今後の課題(7 章「未解決課題」§7.8) |

> 100 体 × 30 step が 4B 単独で完走できた点が本提出の実装上の主要成果。Ollama 並列化と直列バッチ運用を組み合わせ、6GB VRAM 環境でも 100 体スケールの観察が可能であることを実証した。
