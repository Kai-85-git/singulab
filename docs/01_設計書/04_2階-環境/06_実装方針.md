# 06_実装方針

2 階(環境)を Python コードに落とすときの構成。enum + 短文テンプレートだけの **最小実装** に留める。

## 1. ディレクトリ位置

参考: [06_システム設計/02_モジュール構成/01_ディレクトリ構成](../../06_システム設計/02_モジュール構成/01_ディレクトリ構成.md)

```
src/world/
├── __init__.py
├── place.py        # 1階(対象外)
├── field.py        # 1階(対象外)
└── environment.py  # 2階(本書の主担当)
```

`environment.py` は単一ファイルで完結する想定。物理(3階)とは別ファイルに分離し、責務の混在を避ける。

## 2. config.yaml スキーマ

```yaml
environment:
  economy: "neutral"        # "good" | "bad" | "neutral"
  economy_text:             # 任意。省略時はデフォルトテンプレート
    good:    "現在、景気は良い。"
    bad:     "現在、景気は悪く、予算・雇用に緊張感がある。"
    neutral: "現在、景気は可もなく不可もない。"
```

- `economy` のみ必須
- `economy_text` は省略可。省略時は [03_景気の表現方式 §1](03_景気の表現方式.md) のデフォルトを使用
- 設定スキーマ全体は [06_システム設計/03_設定スキーマ](../../06_システム設計/03_設定スキーマ/) と整合

## 3. クラス設計(案)

```python
from dataclasses import dataclass, field
from typing import Literal

EconomyLevel = Literal["good", "bad", "neutral"]

DEFAULT_ECONOMY_TEXT: dict[EconomyLevel, str] = {
    "good":    "現在、景気は良い。",
    "bad":     "現在、景気は悪く、予算・雇用に緊張感がある。",
    "neutral": "現在、景気は可もなく不可もない。",
}

@dataclass(frozen=True)
class Environment:
    economy: EconomyLevel
    economy_text: dict[EconomyLevel, str] = field(default_factory=dict)

    @classmethod
    def from_config(cls, cfg: dict) -> "Environment":
        env_cfg = cfg.get("environment", {})
        economy = env_cfg.get("economy", "neutral")
        if economy not in ("good", "bad", "neutral"):
            raise ValueError(f"invalid economy: {economy}")
        text = {**DEFAULT_ECONOMY_TEXT, **env_cfg.get("economy_text", {})}
        return cls(economy=economy, economy_text=text)

    def prompt_fragment(self) -> str:
        """system prompt 末尾に挿入する 1〜2 文を返す。"""
        return self.economy_text[self.economy]
```

- `Environment` は frozen(1 シミュレーション内で不変)
- `prompt_fragment()` がエージェント生成時に呼ばれ、system prompt の末尾に追記される
- 将来項目を増やすときも `prompt_fragment()` の戻り値に文を追加するだけで済む

## 4. シミュレーションループとの接続

[06_システム設計/05_シミュレーションループ](../../06_システム設計/05_シミュレーションループ/) の 4 フェーズに対し、2 階の関与は **エージェント初期化時のみ**。

| フェーズ | 2 階の関与 |
| --- | --- |
| 起動時(初期化) | `Environment.from_config()` で生成、各 Agent の system prompt に `prompt_fragment()` を挿入 |
| Phase 1: 知覚収集 | 関与なし |
| Phase 2: LLM 推論 | 関与なし(prompt は固定済み) |
| Phase 3: 行動適用 | 関与なし |
| Phase 4: ロギング | 起動時に `economy` 値を run metadata に書く |

- 動的な変化はないので、毎ステップ参照する API は持たない
- これにより 1 階・3 階に比べて圧倒的に実装が薄くなる(意図的)

## 5. ログ

### 5.1 run metadata

シミュレーション開始時に 1 行だけ記録する。

```json
{"timestamp": "2026-04-28T10:00:00Z",
 "scenario": "scenario_local_startup",
 "environment": {"economy": "bad"}}
```

- 比較実験で「どのランがどの景気か」を後から照合できるようにする
- 出力先は `output/run_metadata.json`(または同等のファイル)

### 5.2 LLM 入出力ログ

- 景気文は system prompt に含まれているため、LLM 入出力ログ(`output/messages.jsonl` 等)に自動的に残る
- 別途 environment ログを追加しない(冗長を避ける)

→ ログ全体構造は [06_システム設計/06_ロギング・出力](../../06_システム設計/06_ロギング・出力/) を参照。

## 6. テスト観点

`tests/test_environment.py`(または `test_world.py` 内)で以下をカバーする。

| 観点 | テスト例 |
| --- | --- |
| バリデーション | `economy: "rainy"` のような未知値で `ValueError` |
| デフォルトテンプレート | `economy_text` 省略時にデフォルト文が返る |
| カスタムテンプレート | yaml で文を上書きすると `prompt_fragment()` が反映する |
| 不変性 | `Environment` インスタンスのフィールドが変更不可(`FrozenInstanceError`) |
| プロンプト末尾挿入 | エージェント生成後の system prompt に景気文が末尾に含まれる |

## 7. 拡張時の作法

将来項目を追加する場合([07_将来拡張](07_将来拡張.md))も、以下のパターンで揃える。

1. `Environment` に enum フィールドを追加(数値ではなく enum)
2. デフォルトテンプレート辞書を追加
3. `prompt_fragment()` の戻り値に新しい文を **追記**(段落分けせず短文で並べる)
4. run metadata に値を追加
5. テスト追加

これにより「景気で確立したパターン」を踏襲したまま拡張できる。
