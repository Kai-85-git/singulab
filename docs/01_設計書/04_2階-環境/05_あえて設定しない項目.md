# 05_あえて設定しない項目

2 階で「設定しない」と決めた 3 項目。**観察対象として残す** ために意図的に空にしている。

> 設計の核: [3階層モデル設計 §4](../../01_要件定義/03_機能要件/03_3階層モデル設計.md) — 「あえて設定しない」箇所が説明変数になり、創発の判定材料となる。

## 1. 全体方針

| 項目 | 設定しない理由 | 観察したい創発 |
| --- | --- | --- |
| 時間的プレッシャー | 「急いだ方が良さそう」が自発的に立ち上がるかを観察したい | 緊急性の自然発生、優先順位付け、徹夜・残業文化 |
| 情報の流通量 | 物理(3階)と隣接(1階)から自然に決まる | うわさの速さ、伝言の歪み、ハブ的な人物の出現 |
| 企業文化の雰囲気 | 与えると大企業/スタートアップに固定化される | 文化の自発生成、トップダウン/ボトムアップの分岐 |

## 2. 時間的プレッシャー

### 2.1 何を与えないか

- 「締切まで N 時間」「タスクの所要時間」「期限超過のペナルティ」を **エージェントに伝えない**
- ステップ数の上限はシステム側にあるが、これはエージェントには見せない

### 2.2 観察したい現象

- 全員が同じ作業を漫然と続けるか、それとも誰かが「これ急ぐべきじゃない?」と言い始めるか
- 緊急性が言葉として登場した後、他のエージェントが追従するか無視するか
- 緊急性の言い出しっぺが固定化(=リーダー化)するか、毎回違うか

### 2.3 与えると潰れる創発

- 「締切」を与えた瞬間、全員が同じ緊張度になる
- 緊急性の **発生・伝播・収束** という時系列が観察できなくなる

## 3. 情報の流通量

### 3.1 何を与えないか

- 「今日は情報がよく流れる/流れない」のような流通量プロパティを **持たない**
- 「特定の人だけが知っている情報」を環境量として強制しない

### 3.2 流通量を決めるのは何か

| 要因 | レイヤー | 内容 |
| --- | --- | --- |
| コミュニケーション到達距離 | [3階](../05_3階-物理-重力/) | `comm_radius` 内のエージェントだけが直接聞ける |
| 物理的隣接 | [1階](../03_1階-物/) | 同じ place にいるか、近接しているか |
| 認知限界 | [3階](../05_3階-物理-重力/) | ダンバー数相当の記憶上限 |
| 情報伝達遅延 | [3階](../05_3階-物理-重力/) | リアルタイムでない伝達 |

これら **物理的な制約から自然に流通量が決まる** という設計。2 階で「流通量」を別途与えると物理が空洞化する。

### 3.3 観察したい現象

- うわさが何ステップで全員に届くか(=創発した流通速度)
- 伝言ゲームで内容がどう歪むか
- 「ハブ」になる人物の有無、その人が抜けたときの流通変化

## 4. 企業文化の雰囲気

### 4.1 何を与えないか

- 「トップダウン」「フラット」「飲み会が多い」「家族的」「ドライ」などの文化記述を **ペルソナにも環境にも入れない**
- 役職構造はペルソナで持つが、「文化」は持たない(役職と文化は別物として扱う)

### 4.2 与えると潰れる創発

- 「トップダウン文化です」と書いた瞬間、合意形成は上意下達に固定化される
- 「フラット文化です」と書いた瞬間、誰も指示役を引き受けない傾向が出る
- いずれも **大企業/スタートアップの象限差を初期から焼き付ける** ことになる

### 4.3 観察したい現象

- 同じ集団サイズで複数回回したとき、どの程度文化が安定するか / 揺らぐか
- 「上司に確認してから動く」という規範が自然に立ち上がるか
- 文化の創発が景気・象限とどう相関するか

## 5. 「設定しない」を貫くための運用ルール

実装・運用上、3 項目が紛れ込まないよう以下を守る。

| 場面 | 注意点 |
| --- | --- |
| プロンプト設計 | 景気文以外の環境記述を system prompt に含めない |
| ペルソナ設計 | 「真面目」「協調性が高い」など個人特性は OK。「会社は和気あいあい」のような **集団文化記述** は NG |
| シナリオ yaml | `environment` セクションには `economy` 以外を書かない(将来追加時は [07_将来拡張](07_将来拡張.md) の手続きを踏む) |
| ログレビュー時 | 創発を「文化のせい」と短絡させない。系の挙動を物理 + ペルソナ + 景気で説明できるか先に検証する |

## 6. 創発したかどうかの判定材料

「設定しない」項目が **創発した** かを判定するための観察指標(詳細は [06_システム設計/06_ロギング・出力](../../06_システム設計/06_ロギング・出力/))。

| 創発候補 | 指標例 |
| --- | --- |
| 時間的プレッシャー | 「急ぐ」「締切」等のキーワード出現頻度の時系列、行動の高速化 |
| 情報流通量 | あるメッセージが N 人に届くまでのステップ数、伝言精度 |
| 企業文化 | 同じセリフ・規範の反復使用、特定エージェントの指示頻度の偏り |
