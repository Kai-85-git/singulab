# 02_景気を選んだ理由

2 階で「設定する」のは景気だけ、という決定の根拠。

## 1. なぜ景気が「設定する側」に残ったか

| 観点 | 景気の特性 | 「設定」の妥当性 |
| --- | --- | --- |
| 個人で動かせるか | エージェント個人の意思では変えられない | ✅ 環境量として与えるのが自然 |
| 観察したい創発に直結するか | 直接の観察対象ではないが **前提条件** として効く | ✅ 創発を歪めず、ベースラインに影響する |
| 象限差を固定化するか | 大企業/スタートアップどちらにも独立に効く | ✅ 象限と独立して振れる |
| LLM が状態として理解しやすいか | 「景気が悪い」は一般常識として通じる | ✅ プロンプト 1〜2 文で表現可能 |

逆に、設定すると **創発を潰してしまう** 項目(時間的プレッシャー、情報流通、企業文化)は外している。詳細は [05_あえて設定しない項目](05_あえて設定しない項目.md)。

## 2. 「軽く」の意味

景気を「軽く」与えるとは、以下を全て満たすこと。

- **状態記述に留める**(命令を含まない)
- **1〜2 文で済ませる**(複数段落で世界観を語らない)
- **値を 3 段階に絞る**(`good / bad / neutral`)
- **シミュレーション中は不変**(動的に変化させない)
- **system prompt の末尾に置く**(行動指示より弱い位置)

これにより、景気は「全エージェントの判断にうっすら影響する背景」として機能し、創発(派閥・嘘・通貨・反乱)の前提条件を切り替える比較変数になる。

## 3. 景気が比較実験で果たす役割

ハッカソンの主要な比較軸は [4 象限](../03_1階-物/06_4象限との関係.md) だが、景気は **5 つ目の独立軸** として加わる。

| 比較条件 | バリエーション | 観察したい差 |
| --- | --- | --- |
| 都心 × 大企業 × good | 1 通り | 安定下での意思決定パターン |
| 都心 × 大企業 × bad | 1 通り | 同じ集団が緊張下でどう変わるか |
| 地方 × スタートアップ × bad | 1 通り(デフォルト) | 余裕のない環境でのリーダー選出 |
| 全象限 × neutral | 4 通り | ベースライン |

→ デフォルト割り当ては [04_象限ごとのデフォルト](04_象限ごとのデフォルト.md) を参照。

## 4. 景気を「設定する側」に置くリスクと対策

| リスク | 対策 |
| --- | --- |
| LLM が景気の影響を過剰に演じてしまう | プロンプトを命令形にせず状態記述に留める([03_景気の表現方式](03_景気の表現方式.md)) |
| 景気と象限の効果が分離できなくなる | 比較実験で景気を独立に振り、ANOVA 的に効果を切り分ける |
| 「景気が悪い → 全員が同じ反応」になる | ペルソナの多様性で吸収。短文の状態記述だけなら反応の幅は残る |
| 創発の説明が「全部景気のせい」に収束する | 同じ景気 × 異なる象限の比較で、創発が景気依存か象限依存かを切り分ける |

## 5. 「景気以外も将来は付与したい」場合の判断基準

スコープ拡張時、新しい環境量を「設定する側」に入れるかは以下を確認する([07_将来拡張](07_将来拡張.md))。

- [ ] 個人の意思では動かせない量か
- [ ] 1〜2 文の状態記述で表現可能か(複雑な世界観説明が必要なら却下)
- [ ] 象限と独立に振れるか(どちらかの象限に張り付くなら却下)
- [ ] 観察したい創発を直接潰さないか(例: 「派閥は◯◯」のような記述は派閥の創発を潰す)
