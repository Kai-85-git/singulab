# 03_景気の表現方式

景気を **enum 値 + 短文テンプレート** の組み合わせで表現する。LLM への注入は 1〜2 文の状態記述に留める。

## 1. enum 値

| 値 | 意味 | デフォルトテンプレート |
| --- | --- | --- |
| `good` | 景気は良い | 「現在、景気は良い。」 |
| `bad` | 景気は悪い | 「現在、景気は悪く、予算・雇用に緊張感がある。」 |
| `neutral` | 可もなく不可もない | 「現在、景気は可もなく不可もない。」 |

- 値は `Literal["good", "bad", "neutral"]` として型付け
- 未知の値は起動時に弾く(バリデーションは [06_実装方針 §3](06_実装方針.md))

## 2. なぜ enum か(数値・自由文ではなく)

| 案 | 特徴 | 採否 |
| --- | --- | --- |
| **数値**(0.0〜1.0) | 連続値で粒度が高い | ❌ プロンプト注入が曖昧(「0.3」を LLM がどう解釈するか不明)。比較実験のラベル管理も煩雑 |
| **自由文** | シナリオごとに自由に書ける | ❌ シナリオ間の比較が困難。再現性も落ちる |
| **enum(3 段階)** | 比較実験のセル数が抑えられる、テンプレート管理も容易 | ✅ 採用 |

3 段階(good / bad / neutral)に絞ったのは、4 象限 × 集団サイズの掛け算でセル数が爆発するのを防ぐため。

## 3. テンプレートの設計原則

景気文は次の 5 原則を守る。

| 原則 | NG 例 | OK 例 |
| --- | --- | --- |
| 命令を含まない | 「保守的に振る舞え」 | 「景気は悪い。」 |
| 1〜2 文に留める | 3 段落の世界観説明 | 短く 1 文 |
| 行動を指定しない | 「会議室を使え」 | 状態だけ述べる |
| 過度に感情語を使わない | 「絶望的な不景気」 | 「予算・雇用に緊張感がある」 |
| 主語を「現在」「世の中」に限定 | 「あなたの会社は」 | 「現在、景気は」 |

理由: ペルソナや行動は別レイヤー(エージェント設計)で持つため、景気文がそこに踏み込むと役割が混ざる。

## 4. プロンプト注入位置

景気文は **エージェントの system prompt の末尾** に追加する。

```
[ペルソナ:あなたは都心にあるスタートアップで働くエンジニアである。...]
[役割・目標:...]
[行動可能な action:...]
[現在の状況:現在、景気は悪く、予算・雇用に緊張感がある。]   ← 景気はここ
```

- 末尾に置く理由: 行動指示や役割定義より弱い影響にとどめるため。プロンプトは末尾ほど忘れやすい(LLM 一般傾向)が、それで十分
- 注入はエージェント生成時に 1 回。ステップ途中で書き換えない

→ プロンプト全体構造は [06_システム設計/04_エージェント設計](../../06_システム設計/04_エージェント設計/) を参照。

## 5. 不変性

景気は 1 シミュレーション内で **不変** とする。

| 観点 | 不変にする理由 |
| --- | --- |
| 比較実験の安定性 | 1 ラン中に景気が動くと、観察結果がどの局面の影響か切り分けられない |
| ログの単純化 | run metadata に 1 値書けば済む |
| プロンプトキャッシュ効率 | system prompt が固定なのでプロンプトキャッシュが効きやすい |
| 実装の単純化 | 動的更新ロジック・通知不要 |

動的に変化させたいケースは [07_将来拡張](07_将来拡張.md) で別軸として議論する。

## 6. テンプレートのカスタマイズ

シナリオ別 yaml で文面を上書きできるようにする(MVP では未使用、後続シナリオを見据えた拡張口)。

```yaml
environment:
  economy: bad
  economy_text:
    bad: "現在、世界的なリセッションの最中にある。"
```

- `economy_text` が省略されればデフォルトテンプレート(§1)を使う
- 上書きしてもプロンプトの注入位置・他の原則(§3)は変わらない
