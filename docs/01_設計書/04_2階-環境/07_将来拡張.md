# 07_将来拡張

MVP 後に検討しうる拡張。本フェーズでは扱わないが、復帰経路を明示する。

## 1. 拡張候補

| 拡張 | 概要 | 復帰の手がかり |
| --- | --- | --- |
| **景気の動的変化** | ステップ途中で `good ↔ bad` を切り替える | `Environment` の frozen を解除、ステップごとに `prompt_fragment()` を再評価 |
| **景気の場所別差異** | place ごとに景気を持つ(都心 / 地方が同オフィス内に共存するケース) | `economy: dict[place_id, EconomyLevel]` に拡張 |
| **気候・天候** | 「晴」「雨」「猛暑」など | enum + 短文テンプレートのパターン踏襲 |
| **ニュース・時事** | 業界ニュース、政治イベント | 同上(ただし「文化」に滑り込まないか確認) |
| **為替・原材料価格** | スタートアップ・大企業の財務基盤に効く | 数値で持つか enum で持つかの判断が要る |
| **時間軸**(月日・季節) | 期末・年末・連休 | 「時間的プレッシャー」を観察対象から外すかの再合意が必要 |
| **空気感の限定的導入** | 「空気感」のうち観察を阻害しない最小要素のみ | [05_あえて設定しない項目 §4](05_あえて設定しない項目.md) との整合性を要確認 |

## 2. 「設定する側」に追加するときの判断基準

[02_景気を選んだ理由 §5](02_景気を選んだ理由.md) の判断基準を再掲する。新しい環境量を追加するときは以下を全て満たすか確認する。

- [ ] 個人の意思では動かせない量か
- [ ] 1〜2 文の状態記述で表現可能か(複雑な世界観説明が必要なら却下)
- [ ] 象限と独立に振れるか(どちらかの象限に張り付くなら却下)
- [ ] 観察したい創発を直接潰さないか
- [ ] enum で表現可能か(数値が必須なら採用基準を再検討)

## 3. 「設定しない側」を「設定する側」に動かすときの注意

時間的プレッシャー / 情報流通量 / 企業文化を「やはり与える」と判断する場合、以下を確認する。

| 項目 | 与える前に確認すべきこと |
| --- | --- |
| 時間的プレッシャー | 創発として現れた「緊急性」と、与えた「締切」が混在しないか |
| 情報流通量 | 3階の物理(到達距離・遅延)で表現しきれない流通要因が本当にあるか |
| 企業文化 | 大企業/スタートアップのどちらかに張り付かない中立な記述が可能か |

→ いずれも「与えた瞬間に潰れる創発」がある([05_あえて設定しない項目](05_あえて設定しない項目.md))。判断は要件定義レビューを経る。

## 5. 拡張しない判断のほうが多くなる前提

ハッカソンの主目的は **「設定しないことで何が創発するか」を観察すること** である。拡張は「観察結果から、設定しないと観察できない別の創発が発見された」ときの最終手段とする。安易な拡張は 2 階の哲学([01_議事録からの決定 §3](01_議事録からの決定.md))を壊す。
