# 01_議事録からの決定

2 階(環境)で何を設定するかは、[2026-04-24 ミーティング §5.2](../../02_ミーティング/2026年4月/02_議事録/2026年4月24日.md) で議論し、**景気のみを軽く付与し、他は創発として観察する** と決定した。

## 1. 決定事項

| 項目 | 設定方針 | 理由 |
| --- | --- | --- |
| 景気(良い/悪い) | **軽く付与** | 全体に緩く効く前提条件として |
| 時間的プレッシャー | **設定しない** | 創発として観察したい |
| 情報の流通量 | **設定しない** | コミュニケーション到達距離(3階)と隣接で自然に決まる |
| 企業文化の雰囲気 | **設定しない** | 大企業/スタートアップに固定化されてしまうため |

## 2. 「軽く付与」と「設定しない」の使い分け

景気を「軽く」と表現したのは、**強い命令ではなく状態記述として与える** という意味である。

| 強さ | 例 | 採用 |
| --- | --- | --- |
| 命令型 | 「景気が悪いので保守的に動け」 | ❌(行動を縛りすぎる) |
| 状態記述 | 「現在、景気は悪い。」 | ✅ 採用 |
| 完全省略 | 何も言わない | ❌(全実験で同条件になり比較材料にならない) |

→ 詳細は [03_景気の表現方式](03_景気の表現方式.md) を参照。

## 3. 設計の核(再掲)

> [3階層モデル設計 §4](../../01_要件定義/03_機能要件/03_3階層モデル設計.md) より:「あえて設定しない」箇所が説明変数になる。振り返り時に「何が勝手に創発したか」を判定する材料として機能する。

2 階で「設定しない」と決めた 3 項目(時間的プレッシャー / 情報流通量 / 企業文化)は、**観察対象** として残すために意図的に空にしている。詳細は [05_あえて設定しない項目](05_あえて設定しない項目.md) を参照。

## 4. 議論で見送った案

| 検討案 | 見送り理由 |
| --- | --- |
| 景気を数値(0〜100)で持つ | 比較実験時のラベル管理が煩雑、LLM への注入も曖昧になる。enum で十分 |
| 景気を場所(place)単位で変える | MVP は単一オフィス([1階 §1](../03_1階-物/01_議事録からの決定.md))のため、場所別は不要 |
| 景気をステップ途中で変える | 1 シミュレーション内の比較対象が不安定になる。固定値で実験を切り出す |
| 「企業文化」を最低限だけ与える | どこから与えると象限差が固定化されるか境界が引けない。完全に与えないことで境界問題を回避 |

## 5. この決定が後段に及ぼす影響

- [02_景気を選んだ理由](02_景気を選んだ理由.md): なぜ景気だけが「軽く付与」する 1 項目に選ばれたか
- [03_景気の表現方式](03_景気の表現方式.md): enum + 短文テンプレートという最小実装に直結
- [05_あえて設定しない項目](05_あえて設定しない項目.md): 3 項目が観察対象として残る
- [06_実装方針](06_実装方針.md): モジュールは「enum を読んで短文を注入するだけ」の最小構成
