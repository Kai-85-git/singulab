1 階(物)を Python コードに落とすときの構成。[06_システム設計/02_モジュール構成](../../06_システム設計/02_モジュール構成/) と整合させる。

## 1. ディレクトリ位置

参考: [06_システム設計/02_モジュール構成/01_ディレクトリ構成](../../06_システム設計/02_モジュール構成/01_ディレクトリ構成.md)

```
src/world/
├── __init__.py
├── place.py        # Place / 場所の定義(本書の主担当)
├── field.py        # 座標系・フィールド境界(本書の主担当)
└── environment.py  # 2階(本書の対象外)
```

1 階の責務は **`place.py` と `field.py`** に閉じる。`environment.py` は 2 階の責務であり混在させない。

## 2. クラス設計(案)

### 2.1 PlaceConfig(値オブジェクト)

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class PlaceConfig:
    id: str
    center: tuple[float, float]
    half_size: tuple[float, float]
    capacity: int
    role: str = ""
```

- イミュータブル(frozen=True)。1 シミュレーション中は変更しない
- `__post_init__` で `half_size > 0`、`capacity > 0` を検証

### 2.2 Field(座標系・境界)

```python
class Field:
    def __init__(self, places: list[PlaceConfig]):
        self.places = places
        self.bounds = self._compute_bounds()  # 全 place を含む最小矩形

    def clamp(self, pos: tuple[float, float]) -> tuple[float, float]: ...
    def resolve_place(self, pos: tuple[float, float]) -> PlaceConfig | None: ...
    def is_in_place(self, pos, place: PlaceConfig) -> bool: ...
```

### 2.3 World(1 階のファサード)

```python
class World:
    def __init__(self, config: dict):
        self.places = [PlaceConfig(**p) for p in config["places"]]
        self.field = Field(self.places)
        self.occupancy: dict[str, int] = {p.id: 0 for p in self.places}

    def place_agent(self, agent_id: str, pos): ...
    def move_agent(self, agent_id: str, new_pos) -> tuple[float, float]:
        """capacity 制御 + clamp を行い、最終位置を返す"""
    def agents_in(self, place_id: str) -> list[str]: ...
```

`World` は Simulation Orchestrator から呼ばれる唯一のエントリ。エージェントは `World` を通じてのみ位置を更新する。

## 3. config.yaml との接続

```yaml
places:
  - id: main_office
    center: [0.0, 0.0]
    half_size: [10.0, 10.0]
    capacity: 100
    role: "業務エリア"
  - id: meeting_room
    center: [5.0, 5.0]
    half_size: [2.0, 2.0]
    capacity: 10
    role: "会議室"
```

- 読み込みは `pyyaml` で `dict` にする → `[PlaceConfig(**p) for p in cfg["places"]]`
- スキーマ検証は `pydantic` か手書きの `__post_init__`(MVP は手書きで十分)
- スキーマ詳細は [06_システム設計/03_設定スキーマ](../../06_システム設計/03_設定スキーマ/) を参照

## 4. シミュレーションループとの接続

[06_システム設計/05_シミュレーションループ](../../06_システム設計/05_シミュレーションループ/) の 4 フェーズに対し、1 階は以下のタイミングで呼ばれる。

| フェーズ | 1 階の関与 |
| --- | --- |
| Phase 1: 知覚収集 | `World.agents_in(place_id)` で同じ場所のエージェントを列挙 |
| Phase 2: LLM 推論 | 関与なし(エージェントの責務) |
| Phase 3: 行動適用 | `World.move_agent(agent_id, new_pos)` で位置更新 + capacity 制御 |
| Phase 4: ロギング | 各エージェントの `current_place` をスナップショットに含める |

## 5. テスト観点

`tests/test_world.py` で以下を最低限カバーする。

| 観点 | テスト例 |
| --- | --- |
| バリデーション | `half_size = 0` で起動が失敗する |
| 包含優先 | main_office と meeting_room の重なり位置で `resolve_place` が `meeting_room` を返す |
| capacity 制御 | meeting_room が満員のとき新規入室が拒否され、`pos` が元のまま |
| clamp | フィールド外の `move_agent` 結果が境界内に丸められる |
| 初期配置 | `random_in_place` が `home_place` 内に収まり、capacity を超えない |

## 6. ロギング

[06_システム設計/06_ロギング・出力](../../06_システム設計/06_ロギング・出力/) の `events.jsonl` に以下を出力する。

| イベント | 発火条件 | フィールド |
| --- | --- | --- |
| `place_change` | `current_place` が前ステップから変化 | `agent_id, from, to, step` |
| `place_entry_denied` | capacity 制限で入室拒否 | `agent_id, place_id, step` |
| `clamp_to_field` | フィールド境界で clamp 発生 | `agent_id, attempted_pos, clamped_pos, step` |

これらは創発指標(派閥・選別・拒否頻度)の集計入力となる。
