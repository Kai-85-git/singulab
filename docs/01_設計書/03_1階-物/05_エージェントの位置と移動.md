# 05_エージェントの位置と移動

エージェントが「どこにいて、どう動くか」のルール。参考実装の方式を踏襲しつつ、本プロジェクトの観察観点に合わせて補足する。

## 1. 位置の表現

各エージェントは以下を保持する。

| 属性 | 型 | 説明 |
| --- | --- | --- |
| `pos` | `(float, float)` | 現在位置 (x, y) |
| `current_place` | `str \| None` | 現在所属する place の id([03_場の構造定義 §4](03_場の構造定義.md) の優先順位で算出) |
| `home_place` | `str` | 初期所属 place の id(リセットや復帰判定の基準) |

`current_place` は派生値であり、毎ステップ `pos` から再計算する(状態の重複を避ける)。

## 2. 移動アクション

参考実装に倣い、1 ステップで取れる移動アクションは **5 種類** に限定する。

| アクション | 効果 | 備考 |
| --- | --- | --- |
| `move_north` | y を `+step_size` | y 軸正方向 |
| `move_south` | y を `-step_size` | y 軸負方向 |
| `move_east` | x を `+step_size` | x 軸正方向 |
| `move_west` | x を `-step_size` | x 軸負方向 |
| `stay` | 位置変えず | 同じ場所での会話・思考に専念 |

- `step_size` の初期値: **1.0**(無次元)。フィールド規模 20×20 に対して 1 ステップで 5% 程度動く感覚
- 斜め移動は MVP では持たない。観察したい現象は移動の自由度より「集まる/離れる」の傾向であり、4 方向で十分

## 3. 移動の決定

移動は **エージェントの LLM 出力の一部** として決まる(参照: [06_システム設計/04_エージェント設計](../../06_システム設計/04_エージェント設計/))。

```json
{
  "thought": "...",
  "message": "...",
  "action": "move_east"
}
```

LLM が無効なアクションを返した場合は `stay` にフォールバックし、ログに記録する。

## 4. 境界処理(clamp)

移動結果がフィールド有効領域を超える場合、両軸とも main_office の矩形内に丸める。

```python
def clamp_to_field(pos, field_bounds):
    (xmin, xmax), (ymin, ymax) = field_bounds
    x, y = pos
    return (max(xmin, min(xmax, x)),
            max(ymin, min(ymax, y)))
```

- `field_bounds` は `main_office.center ± main_office.half_size` から導出
- 壁にぶつかった場合は「動こうとしたが動けなかった」状態として扱う(=実質 `stay`)

## 5. 場所の遷移と capacity 制御

移動先座標が別の place に入る場合、その place の現在人数 ≥ capacity であれば **入室を拒否** する。

```python
def apply_movement(agent, new_pos, places, occupancy):
    target = resolve_place(new_pos, places)
    if target and occupancy[target.id] >= target.capacity:
        if target.id != agent.current_place:
            return agent.pos  # 入れない → 元の位置に留まる
    return new_pos
```

- 既に中にいるエージェントは追い出されない
- 拒否されたケースは `events.jsonl` に `place_entry_denied` として記録

## 6. 近傍判定

「同じ場所にいる/コミュニケーション可能な範囲にいる」の判定は本ドキュメントでは扱わない。

- 同じ place にいるか: `current_place` の一致で判定([04_場の内訳と役割](04_場の内訳と役割.md))
- コミュニケーション到達距離: [3階(物理) `comm_radius`](../../05_3階-物理-重力/) の責務

1 階の責務は **位置を確定させること** までであり、その位置を使った相互作用ルールは 3 階に分離する。

## 7. 初期配置

シミュレーション開始時の `pos` 決定方法:

| 方式 | 説明 | デフォルト |
| --- | --- | --- |
| `random_in_place` | `home_place` の矩形内に一様分布で散らす | ✅ デフォルト |
| `fixed` | config で座標直書き | デバッグ・再現性確認用 |
| `cluster` | 中心からガウス分布で集める | 初期凝集の影響を見たい時 |

- 乱数シードは `config.yaml` の `random_seed` を使用([06_システム設計/03_設定スキーマ](../../06_システム設計/03_設定スキーマ/))
- 初期配置で capacity 違反が起きないよう、配置時にもチェックする
