# 03_場の構造定義

`config.yaml` に置く `places` セクションのスキーマ定義。

## 1. YAML スキーマ(案)

```yaml
places:
  - id: main_office          # 必須・一意
    center: [0.0, 0.0]       # 必須・float×2
    half_size: [10.0, 10.0]  # 必須・float×2(両方 > 0)
    capacity: 100            # 必須・int(> 0)
    role: "業務エリア"       # 任意・人間向けラベル
  - id: meeting_room
    center: [5.0, 5.0]
    half_size: [2.0, 2.0]
    capacity: 10
    role: "会議室"
```

## 2. 各フィールドの意味

| フィールド | 型 | 必須 | 意味 | 単位/制約 |
| --- | --- | --- | --- | --- |
| `id` | string | ✅ | 場所の一意識別子。ログ・統計のキーに使う | snake_case 推奨、英数字 + `_` |
| `center` | `[float, float]` | ✅ | 矩形の中心座標 (x, y) | 無次元(メートル相当の感覚) |
| `half_size` | `[float, float]` | ✅ | 中心から各辺までの距離 (hx, hy)。実際の幅/高さは 2×half_size | 両成分 > 0 |
| `capacity` | int | ✅ | 同時収容できるエージェント数の上限 | > 0 |
| `role` | string | ❌ | 可視化・プロンプト挿入用の人間向けラベル | 自由記述 |

## 3. バリデーションルール

`World` モジュール初期化時に `config.yaml` を読み込み、以下を検証して失敗時は起動前にエラー終了する。

| ルール | チェック内容 | 失敗時メッセージ例 |
| --- | --- | --- |
| `id` 一意 | 全 place の id が重複しない | `place id "main_office" is duplicated` |
| `half_size > 0` | 両成分が正 | `place "x" has non-positive half_size` |
| `capacity > 0` | 整数かつ正 | `place "x" capacity must be positive int` |
| 内包整合 | 包含関係にある place は内側の capacity ≤ 外側の capacity を満たす | `meeting_room capacity exceeds main_office capacity` |
| エージェント総数 | エージェント総数 ≤ 全 place の capacity 合計 | `total agents (120) exceed total capacity (100)` |

> ⚠️ **重なりは禁止しない**: 「main_office が meeting_room を内包する」前提のため、矩形重なり自体は許容する。重なる場合の所属判定は §4 で定義する。

## 4. 重なる place の優先順位

複数の place の矩形に同時に含まれる場合、**矩形面積が小さい順** に優先する。

```python
def resolve_place(pos, places):
    candidates = [p for p in places if is_in_place(pos, p)]
    if not candidates:
        return None  # フィールド境界外。clamp 後に再評価
    return min(candidates, key=lambda p: p.half_size[0] * p.half_size[1])
```

理由:

- 「main_office に内包される meeting_room」の構造を直感的に表現できる
- 内側の place ほど目的が具体的(会議など)であり、所属として意味が強い
- 将来「個室 → 会議室 → オフィス」のように 3 段階以上の入れ子になっても同じ規則で対応できる

## 5. デフォルト値

`config/base.yaml` に以下のデフォルトを置く想定([06_システム設計/03_設定スキーマ](../../06_システム設計/03_設定スキーマ/) と整合)。

```yaml
places:
  - id: main_office
    center: [0.0, 0.0]
    half_size: [10.0, 10.0]
    capacity: 100
    role: "業務エリア"
  - id: meeting_room
    center: [5.0, 5.0]
    half_size: [2.0, 2.0]
    capacity: 10
    role: "会議室"
```

シナリオ別 YAML(例: `scenario_bar_fire.yaml`)はこのデフォルトを上書きする。

## 6. フィールド境界

- フィールドは「最大の place(= main_office)を含む最小の矩形」を有効領域とする
- 境界外座標は移動時に **clamp**(両軸とも main_office の矩形内に丸める)([05_エージェントの位置と移動 §4](05_エージェントの位置と移動.md))
- 境界外を許す設定は MVP では持たない([08_スコープ外](08_スコープ外.md))
