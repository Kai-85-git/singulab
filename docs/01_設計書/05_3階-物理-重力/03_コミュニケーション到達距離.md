# 03_コミュニケーション到達距離

エージェント i の発話が、どの j に届くかを決める空間的制約。

## 1. 意義

音声・ささやきが届く物理範囲を表現する。**「全員に同時に話しかける」LLM の挙動を物理的に抑える** ことで、近接ペアでのみ成立する会話・うわさの伝播・派閥形成を観察可能にする。

## 2. 定義

エージェント i の発話メッセージは、以下を満たす j のみが受信できる。

```
|pos_i - pos_j| < r_comm  かつ  i.current_place == j.current_place
```

- 距離計算はユークリッド距離(1 階で 2D 連続座標を採用したため)
- 同一 place 縛りは「壁による遮蔽」を簡易表現するための補強条件
  - 1 階の place は重なる場合があるため(main_office が meeting_room を内包)、`current_place` の一致で内/外を区別する
  - 内側 place(meeting_room)にいる i の発話は、外側(main_office のみ)の j には届かない
- `r_comm` は **place ごとに異なってもよい**(下記 §4)

## 3. 仮値

集団サイズで切り替える前提。実装上は config で指定する。

| 集団 | r_comm | 解釈 |
| --- | --- | --- |
| 小集団(2〜10 人) | 15.0 | オフィス全体(20×20)をほぼカバー。誰の声でも届く |
| 中集団(20〜30 人) | 8.0 | オフィスの半径 40% 程度。届く相手は限定 |
| 大集団(100 人) | 3.0〜5.0 | 近傍のみ。遠い人の声は物理的に届かない |
| 会議室内(meeting_room) | 5.0(または place 半径以上) | 会議室は密室なので全員に届く想定 |

## 4. place ごとの r_comm

`r_comm` を place 単位で持てるようにする(MVP は global 1 値だが、構造として用意する)。

```yaml
world_laws:
  communication_radius: 5.0     # デフォルト(global)
  communication_radius_overrides:
    meeting_room: 10.0          # 会議室は壁で囲まれて全員に届く想定
```

- `overrides` で place id を指定すると、その place 内のエージェントの発話に適用される
- 未指定の place は global 値を使う

## 5. 受信判定アルゴリズム

```python
def deliverable_recipients(sender, all_agents, r_comm_global, r_comm_overrides):
    r = r_comm_overrides.get(sender.current_place, r_comm_global)
    recipients = []
    for j in all_agents:
        if j.id == sender.id:
            continue
        if j.current_place != sender.current_place:
            continue
        if dist(sender.pos, j.pos) < r:
            recipients.append(j)
    return recipients
```

- 計算量は O(N)。MVP の N=100 では十分
- 大規模化したら place ごとに事前グルーピングして O(N_place) に落とせる

## 6. 「届かなかった」の扱い

- 発話自体は実行される(エージェントの thought / action は記録される)
- 単に **受信側に届かない** だけ。記録上は「発話したが宛先がいなかった」
- ログには `(送信元, 宛先候補=空, 配送結果=no_recipient)` を残す
- これにより「誰にも聞かれずに独り言を続けたエージェント」も観察可能

## 7. 観察したい現象との対応

| 観察対象 | r_comm が果たす役割 |
| --- | --- |
| 派閥形成 | 物理的に近い人同士でしか会話できない → 同じ場所にいる人で派閥が固まる |
| うわさの伝播速度 | r_comm が小さいほど、ハブとなる人物を介さないと遠くに届かない |
| 会議室の特権性 | 会議室の overrides で全員に届くと、会議室=情報独占の場になる |
| 嘘・歪曲 | 直接聞いた人と伝聞で聞いた人の差が観察できる |

## 8. 検討した代替案

| 案 | 概要 | 採否 |
| --- | --- | --- |
| 全員に届く(no constraint) | LLM デフォルト挙動 | ❌ 創発が消える |
| place 単位で「中の人全員に届く」 | place を最小単位とする | ❌ 同 place 内の距離感が消える、近接ペアの会話が観察できない |
| 距離による減衰(確率的に届く) | `p = exp(-d/r)` で確率的配送 | ❌ MVP では複雑度に見合わない。決定論的 0/1 で十分 |
| 視線・遮蔽物を考慮 | 壁・什器を持つ | ❌ MVP スコープ外。current_place 一致で代替 |

## 9. ログ

[07_実装方針 §6](07_実装方針.md) のログに加え、本法則特有の項目:

| イベント | フィールド |
| --- | --- |
| `message_delivered` | `sender, recipient, distance, r_comm_used, place` |
| `message_out_of_range` | `sender, intended_or_all_in_place, distance, r_comm_used` |

距離記録があると、後で「届く距離はどこから問題になり始めたか」を可視化できる。
