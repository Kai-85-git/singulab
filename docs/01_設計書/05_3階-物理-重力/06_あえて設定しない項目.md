# 06_あえて設定しない項目

3 階で「設定しない」と決めた 2 項目。**本シミュレーションの最大の観察論点**。

> 設計の核: [3階層モデル設計 §4](../../01_要件定義/03_機能要件/03_3階層モデル設計.md) — 「あえて設定しない」箇所が説明変数になり、創発の判定材料となる。

## 1. 全体方針

| 項目 | 設定しない理由 | 観察したい創発 |
| --- | --- | --- |
| 合意形成ルール | どの方法が自然発生するかが本シミュレーションの核 | 多数決 / 全会一致 / リーダー決定 / 沈黙のうちに諦める |
| 発言権の分配 | 与えると結果がそのとおりになる | 自然発生する「よく発言する人」、発言の偏り |

## 2. 合意形成ルール

### 2.1 何を与えないか

- 「この集団は多数決で決める」「全会一致で決める」「リーダーの一任で決める」を **与えない**
- 「誰が決定者か」も与えない(役職としての「上司」はペルソナで表現可能だが、決定権は与えない)
- 「合意したかどうか」の判定基準も与えない(「何をもって合意か」自体が観察対象)

### 2.2 観察したい現象

| 現象 | 創発の指標 |
| --- | --- |
| 多数決の自然発生 | 「賛成」「反対」のカウントが行動に影響している兆候 |
| 全会一致の自然発生 | 1 人でも反対すると行動が止まる |
| リーダー決定 | 特定エージェントの発話が他の発話を上書きしている |
| 沈黙のうちに諦める | 議題が出されたが応答がなく、自然消滅 |
| **これらの混在** | 議題によって決め方が変わる(柔軟な使い分け) |

### 2.3 与えると潰れる創発

- 「多数決で決めろ」と書いた瞬間、全議題が多数決になる
- 「リーダーが決める」と書くと、リーダー以外の発言が形骸化する
- いずれも **「集団がどう決めるか」を集団自身に発見させる** 観察機会を奪う

### 2.4 「合意した」をどう判定するか(事後解析)

設定しない以上、「合意したかどうか」は事後解析で推定する。

| 推定方法 | 内容 |
| --- | --- |
| 行動の収束 | 全エージェントが同じ方向に動き始めた → 合意成立の兆候 |
| 反対意見の消滅 | 反対発話が一定ステップ続かない → 合意成立 |
| 事後の言及 | 「さっき決まったことだけど」のような過去合意への言及がある |

これらの指標は [06_システム設計/06_ロギング・出力](../../06_システム設計/06_ロギング・出力/) の創発指標として実装する。

## 3. 発言権の分配

### 3.1 何を与えないか

- 「あなたは発言が多いタイプ」「あなたは聞き手」のような **発言頻度の指定をしない**
- 「上司の発言を優先しろ」のような **優先順位を与えない**
- 「特定の議題は誰が決める」のような **領域別の権限を与えない**

### 3.2 観察したい現象

| 現象 | 創発の指標 |
| --- | --- |
| 「よく発言する人」の自然発生 | 発言頻度の分布がべき乗的になる(少数の人が大半を発言) |
| 沈黙する人の自然発生 | 一度も発言しないエージェントの数 |
| 場による発言権の差 | 会議室で発言する人と main_office で発言する人が違う |
| 状況による発言権の変化 | 火事イベント発生時に普段沈黙していた人が発言する |

### 3.3 与えると潰れる創発

- 「Alice は発言が多い」と書いた瞬間、Alice が常に主導するパターンに固定化
- 「上司を優先」と書くと、組織図がそのまま発言頻度になる
- いずれも **「発言権はどう分配されるか」を集団に発見させる** 機会を奪う

## 4. 「設定しない」を貫く運用ルール

実装・運用上、2 項目が紛れ込まないよう以下を守る。

| 場面 | 注意点 |
| --- | --- |
| プロンプト設計 | system prompt に「決定方法」「発言頻度」を入れない |
| ペルソナ設計 | 「真面目」「外向的」など個人特性は OK。「リーダー役」「決定権者」は NG |
| シナリオ yaml | `world_laws` に決定ルール・発言頻度を書かない |
| ログレビュー | 創発を「ペルソナの設計のせい」と短絡させない。プロンプト全体を見て発言権が暗黙に与えられていないか検証 |

## 5. 「設定する 3 法則」が「設定しない 2 項目」を支える

3 法則がない状態で「合意形成」を観察しても、無限記憶・全員同時通信のため意味のある創発が出ない。3 法則が **物理的な舞台装置** として働くからこそ、合意形成・発言権が観察対象になる。

| 3 法則 | 2 項目への影響 |
| --- | --- |
| 到達距離 | 「全員に向けた発言」が物理的に不可能 → 誰に話すか自体が選択になる |
| 遅延 | 「先に発言した人」「後で知った人」の差が生まれ、発言タイミングが意味を持つ |
| 認知限界 | 「覚えられている人」が発言権を獲得しやすくなる現象が観察可能 |

## 6. 創発したかどうかの判定材料

[06_システム設計/06_ロギング・出力](../../06_システム設計/06_ロギング・出力/) で集計する観察指標。

| 創発候補 | 指標例 |
| --- | --- |
| 合意形成の様式 | 議題提起から行動収束までのステップ数、反対意見の数の時系列 |
| 多数決的傾向 | 「賛成」「反対」のカウントが行動と相関するか |
| リーダー決定的傾向 | 特定エージェントの発話を誰がどれだけ引用するか |
| 発言権の偏り | 発言頻度のジニ係数、上位 20% が全体の何 % を発言したか |
| 沈黙する人の割合 | 1 ラン中、発言ゼロのエージェントの割合 |
