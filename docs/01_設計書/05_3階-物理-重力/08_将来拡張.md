# 08_将来拡張

MVP 後に検討しうる拡張。本フェーズでは扱わないが、復帰経路を明示する。

## 1. 拡張候補

| 拡張 | 概要 | 復帰の手がかり |
| --- | --- | --- |
| **到達距離の方向性** | ささやきは狭い、大声は広い | 発話 action に `volume` を持たせ、r_comm を `r_base * volume` に変える |
| **遅延のノイズ(伝言ゲーム)** | 経由人数に応じて内容が歪む | DeliveryQueue で経由ごとに summary を LLM に再要約させる |
| **place 間の伝聞配送** | メッセンジャー役が情報を別 place に持ち込む | エージェント移動時に保有メッセージを移動先 place の遅延キューに移管 |
| **認知限界の個人差** | 年齢・属性で K を変える | `Agent` ごとに `cognitive_limit` を持つ(現在は global) |
| **階層的記憶** | 短期(揮発)+ 長期(K 件) | AgentMemory に `working_memory` と `long_term_memory` を分離 |
| **環境由来の物理変化** | 騒音で通信が弱まる、距離が広がる | 2 階の `environment` から 3 階の数値を動的に変える結合を作る |
| ~~**視覚到達距離**~~(部分実装済 2026-05-01) | ~~「誰が見えるか」を音声と分けて持つ~~ | **AlienEvent では `near_radius` / `visible_radius` を実装**(要件定義 02_エージェント属性 §6.5)。エージェント間の視認は未対応 |
| **疲労・集中力** | ステップ経過で r_comm/K が下がる | `Agent` に `fatigue` を持たせ、3 法則の閾値に係数を掛ける |
| **重力の比喩を超えた物理量** | 拡散・反応速度(細胞シナリオ用) | `physics/diffusion.py` 等を追加 |

## 2. 拡張の優先順位

ハッカソンでの観察結果次第で優先順位が変わる。**観察したい現象が見えなかったとき** に優先する候補:

| 観察できなかった現象 | 優先する拡張 |
| --- | --- |
| 伝言ゲーム的な歪曲 | 遅延ノイズ |
| 派閥が固まらない | 認知限界の個人差(K を狭める) |
| 会議室外への情報漏洩 | place 間の伝聞配送 |
| 一日経過の影響 | 疲労・集中力 |

## 3. 「設定する側」を増やすときの判断基準

[02_設計の核 §3](02_設計の核.md) の 3 基準を再掲する。新法則を追加するときは以下を全て満たすか確認する。

- [ ] 個人の意思では破れない(物理・生理の限界か)
- [ ] LLM が無自覚に超越する(明示制約しないと無限になる)
- [ ] 観察したい創発に直結しない(前提条件か)

## 4. 「設定しない側」を「設定する側」に動かすときの注意

合意形成ルール / 発言権を「やはり与える」と判断する場合、以下を確認する。

| 項目 | 与える前に確認すべきこと |
| --- | --- |
| 合意形成ルール | 創発として現れた決定パターンと、与えたルールが混在しないか。シミュレーション目的そのものが失われないか |
| 発言権の分配 | 創発として観察された発言頻度と、与えた優先順位が混在しないか |

→ いずれも「与えた瞬間に潰れる創発」がある([06_あえて設定しない項目](06_あえて設定しない項目.md))。要件定義レビューを必ず経る。

## 6. 拡張しない判断のほうが多くなる前提

ハッカソンの主目的は **「3 法則という最小制約下で、合意形成と発言権がどう創発するか」を観察すること** である。拡張は「観察結果から、現在の 3 法則だけでは観察できない別の創発が発見された」ときの最終手段とする。安易な拡張は 3 階の哲学([02_設計の核](02_設計の核.md))を壊す。
