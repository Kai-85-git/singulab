# 05_認知限界(ダンバー数)

一人のエージェントが「覚えていられる他者」の上限。LLM の無限記憶を抑え、**忘却・思い込み・親密圏の形成** を観察可能にする。

## 1. 意義

- LLM はコンテキストに収まる限り全エージェントの過去発話を完璧に保持できる
- 一方、人間は安定した社会関係を保てる人数に上限がある(ダンバー数)
- これを与えないと、100 人集団でも全員が全員を完璧に覚えており、派閥・親密圏・忘却がそもそも存在しなくなる

## 2. 定義

各エージェントの Memory は **他者ごとのエントリ** を持ち、保持数を K に制限する。

```python
class AgentMemory:
    def __init__(self, k: int):
        self.k = k
        self.entries: dict[str, MemoryEntry] = {}  # other_agent_id -> entry
        # 各 entry は last_interaction_step を持つ

    def update(self, other_id: str, info: dict, current_step: int):
        if other_id in self.entries:
            self.entries[other_id].update(info, current_step)
            return
        if len(self.entries) >= self.k:
            self._evict_oldest()
        self.entries[other_id] = MemoryEntry(other_id, info, current_step)

    def _evict_oldest(self):
        oldest = min(self.entries, key=lambda k: self.entries[k].last_interaction_step)
        del self.entries[oldest]
```

- **超過時の処理**: LRU(Least Recently Used)。最後に関わってから時間が経った相手から忘れる
- **忘却 = 完全削除**:「うっすら覚えている」はまずは持たない(将来拡張)

## 3. 仮値

| パラメータ | 値 | 根拠 |
| --- | --- | --- |
| K(小集団 2〜10 人) | 10 | 全員把握可能。キャパに引っかからない |
| K(中集団 20〜30 人) | 15〜20 | 半分は忘れる。親密圏が生まれる |
| K(大集団 100 人) | 30〜50 | ダンバー数の下限(親密圏 ~5、信頼圏 ~15、知人圏 ~50)を目安 |

> ダンバー数は元来 ~150 だが、本シミュレーションでは「短い時間で派閥が観察できる規模」を優先し下限を採用。

## 4. K の選定指針

K は **観察したい現象が起きる範囲** で選ぶ。

| K と集団サイズの関係 | 起きる現象 |
| --- | --- |
| K ≥ 集団サイズ | 全員把握 → 親密圏が観察できない |
| K = 集団サイズの 1/2 程度 | 派閥・親密圏が立ち上がる |
| K ≪ 集団サイズ(1/4 以下) | 「知らない人」が大半。閉じた小グループが固定化 |

シナリオごとに「この集団でどんな分布を見たいか」から K を逆算する。

## 5. Memory エントリの中身

各エントリには以下を保持する。

| フィールド | 型 | 用途 |
| --- | --- | --- |
| `other_id` | str | 対象エージェント ID |
| `last_interaction_step` | int | LRU 判定用 |
| `summary` | str | LLM が生成する要約(性格・関係性) |
| `recent_messages` | list[Message] | 直近の発話(N 件まで) |
| `tags` | list[str](optional) | 関係ラベル(将来拡張: 「同僚」「上司」など) |

`summary` の更新タイミングは [06_システム設計/04_エージェント設計](../../06_システム設計/04_エージェント設計/) を参照。

## 6. プロンプト組み立てとの接続

`Agent.build_prompt()` 時に Memory から情報を取り出し、K 件以内に収めた状態で LLM に渡す。

```python
def render_memory_for_prompt(memory: AgentMemory) -> str:
    sorted_entries = sorted(memory.entries.values(),
                            key=lambda e: e.last_interaction_step,
                            reverse=True)
    lines = []
    for e in sorted_entries:
        lines.append(f"- {e.other_id}: {e.summary}")
    return "\n".join(lines)
```

- 全エントリ(最大 K 件)を出力するため、プロンプトに収まる前提
- K=50 でも summary を 1 行に抑えれば collateral 50 行 ≒ 数百トークン → 問題なし

## 7. 「忘れた」エージェントとの再接触

K を超えて忘却したエージェントと再び関わったとき:

| 状況 | 挙動 |
| --- | --- |
| 同じ会議室で会う | 新規エントリとして再登録される(過去の関係は失われた状態) |
| 過去の発話を他者から伝聞で聞く | 名前を知らないので「誰?」状態。情報の信頼性が落ちる |

これは **「久しぶりに会った同僚を思い出せない」** という人間的現象を再現する。

## 8. 観察したい現象との対応

| 観察対象 | 認知限界が果たす役割 |
| --- | --- |
| 派閥形成 | 同じ顔ぶれと頻繁に関わる人だけが Memory に残る → 自然に派閥化 |
| 既得権益 | 「上司」「同僚」を覚えている人だけが意思決定に参加できる |
| 忘却による意思決定の歪み | 過去の合意を忘れた人が違う判断をする |
| 嘘の見破り | 過去の発話を覚えている相手にしか嘘を見破られない |

## 9. 検討した代替案

| 案 | 概要 | 採否 |
| --- | --- | --- |
| 制限なし(LLM に丸投げ) | コンテキストに収まる分だけ持つ | ❌ 観察したい現象が消える |
| Working memory のみ制限 | 全件保持、参照は K 件 | △ プロンプト膨張のリスクあり。MVP は採用しない |
| 確率的忘却(random eviction) | LRU ではなくランダムに忘れる | ❌ 観察解釈が難しくなる、ノイズが大きい |
| 関係強度に応じた保持(重要度) | 「重要な相手は忘れない」 | ❌ 重要度の定義が必要。まずは LRU で開始 |
| 階層的記憶(短期・長期) | 短期は揮発、長期は K 件 | △ 将来拡張([08_将来拡張](08_将来拡張.md))で検討 |

## 10. ログ

| イベント | フィールド |
| --- | --- |
| `memory_added` | `agent_id, target_id, step` |
| `memory_evicted` | `agent_id, target_id, last_interaction_step, current_step` |
| `memory_re_encountered` | `agent_id, target_id, gap_steps`(忘れていた相手に再会) |

これらは「派閥がいつ固まったか」「いつ崩れたか」の解析素材になる。
