# 07_実装方針

3 階(世界の法則)を Python コードに落とすときの構成。**Orchestrator のメッセージ配送と Agent の Memory 更新** に分散して実装する。

## 1. ディレクトリ位置

参考: [06_システム設計/02_モジュール構成/01_ディレクトリ構成](../../06_システム設計/02_モジュール構成/01_ディレクトリ構成.md)

```
src/
├── physics/                # 3階(本書の主担当)
│   ├── __init__.py
│   ├── base.py             # 抽象 Physics
│   ├── communication.py    # 到達距離 + 遅延
│   └── cognition.py        # 認知限界(Memory への作用)
├── agent/
│   └── memory.py           # 認知限界の実装が入る場所
└── simulation.py           # Orchestrator(配送ロジックの呼び出し元)
```

3 法則のうち **到達距離 + 遅延は `physics/communication.py`**、**認知限界は `agent/memory.py`** に分かれて実装される(対象モジュールが違うため自然に分離)。

## 2. config.yaml スキーマ

```yaml
world_laws:
  communication_radius: 5.0           # デフォルト到達距離
  communication_radius_overrides:     # 任意。place 単位で上書き
    meeting_room: 10.0
  message_delay:
    same_place_near: 0
    same_place_far: 1
    cross_place: 3                    # MVP では未使用(将来拡張)
  cognitive_limit: 30                 # Memory 保持上限 K
```

- 全項目に妥当な範囲のバリデーションを掛ける(§4)
- 設定スキーマ全体は [06_システム設計/03_設定スキーマ](../../06_システム設計/03_設定スキーマ/) と整合

## 3. クラス設計(案)

### 3.1 WorldLaws(値オブジェクト)

```python
from dataclasses import dataclass, field

@dataclass(frozen=True)
class MessageDelay:
    same_place_near: int = 0
    same_place_far: int = 1
    cross_place: int = 3

@dataclass(frozen=True)
class WorldLaws:
    communication_radius: float
    communication_radius_overrides: dict[str, float] = field(default_factory=dict)
    message_delay: MessageDelay = field(default_factory=MessageDelay)
    cognitive_limit: int = 30

    @classmethod
    def from_config(cls, cfg: dict) -> "WorldLaws":
        ...  # バリデーションを含む

    def comm_radius_for(self, place_id: str) -> float:
        return self.communication_radius_overrides.get(place_id,
                                                      self.communication_radius)
```

### 3.2 CommunicationPhysics(配送ロジック)

```python
class CommunicationPhysics:
    def __init__(self, laws: WorldLaws):
        self.laws = laws
        self.queue = DeliveryQueue()

    def determine_recipients(self, sender, all_agents) -> list:
        r = self.laws.comm_radius_for(sender.current_place)
        return [a for a in all_agents
                if a.id != sender.id
                and a.current_place == sender.current_place
                and dist(sender.pos, a.pos) < r]

    def determine_delay(self, sender, recipient) -> int:
        if sender.current_place == recipient.current_place:
            r = self.laws.comm_radius_for(sender.current_place)
            return (self.laws.message_delay.same_place_near
                    if dist(sender.pos, recipient.pos) < r
                    else self.laws.message_delay.same_place_far)
        return self.laws.message_delay.cross_place

    def schedule_delivery(self, sender, msg, all_agents, current_step: int):
        recipients = self.determine_recipients(sender, all_agents)
        for r in recipients:
            d = self.determine_delay(sender, r)
            self.queue.schedule(current_step + d, r.id, msg)
```

## 4. バリデーション

| 項目 | チェック内容 | 失敗時メッセージ例 |
| --- | --- | --- |
| `communication_radius` | > 0 | `communication_radius must be positive` |
| `communication_radius_overrides[k]` | 全成分 > 0 | `override for "x" must be positive` |
| `message_delay.*` | 全成分 ≥ 0 の整数 | `message_delay must be non-negative int` |
| `cognitive_limit` | > 0 の整数 | `cognitive_limit must be positive int` |
| place id 整合 | overrides の key が `places` に存在 | `override for unknown place "x"` |

## 5. 仮値の調整プロセス

[02_設計の核 §4](02_設計の核.md) の通り、仮値は実験で振って調整する。

| ステップ | 内容 |
| --- | --- |
| 1 | デフォルト仮値で 1 ラン回す |
| 2 | 観察したい現象(派閥・うわさ・合意)が 1 ラン内に観察できるかを確認 |
| 3 | 観察できなければ仮値を変える(例: r_comm を半分に、K を 1/2 に) |
| 4 | 観察できたら、その仮値を **シナリオごとのデフォルト** として保存 |
| 5 | 比較実験では仮値を ±50% で振って感度を見る |

## 6. シミュレーションループとの接続

[06_システム設計/05_シミュレーションループ](../../06_システム設計/05_シミュレーションループ/) の 4 フェーズに対する関与:

| フェーズ | 3 階の関与 |
| --- | --- |
| 起動時(初期化) | `WorldLaws.from_config()` 生成、各 Agent に `cognitive_limit` を渡す |
| Phase 1: 知覚収集 | `CommunicationPhysics.queue.pop_due(t)` で受信予定メッセージを取り出して Agent に渡す |
| Phase 2: LLM 推論 | 関与なし |
| Phase 3: 行動適用 | 発話を `schedule_delivery()` で配送スケジュール |
| Phase 4: ロギング | 配送結果・Memory 更新を jsonl に記録 |

## 7. ログ

[06_システム設計/06_ロギング・出力](../../06_システム設計/06_ロギング・出力/) の `events.jsonl` に以下を出力する。

| イベント | 発火元 |
| --- | --- |
| `message_delivered` / `message_out_of_range` | CommunicationPhysics |
| `message_scheduled` / `message_delivered_with_delay` / `message_lost` | DeliveryQueue |
| `memory_added` / `memory_evicted` / `memory_re_encountered` | AgentMemory |

これらは創発指標(派閥安定度、伝播速度、忘却率)の集計入力となる。

## 8. テスト観点

`tests/test_physics.py` で以下を最低限カバーする。

| 観点 | テスト例 |
| --- | --- |
| 到達距離 | r_comm 境界の内/外で `determine_recipients` の結果が変わる |
| place 一致縛り | 異なる place のエージェントは r_comm 内でも除外される |
| place 上書き | overrides 指定 place で global と異なる r が使われる |
| 遅延 0 | 同 place 近距離は同ステップで届く |
| 遅延 > 0 | 同 place 遠距離は次以降のステップで届く |
| Memory 上限 | K 件超過で最古エントリが削除される |
| Memory 再接触 | 削除後の再接触で `memory_re_encountered` イベントが立つ |
