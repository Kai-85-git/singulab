# 3 モデル JSON 出力品質検証(2026-04-28)

| 項目 | 値 |
| --- | --- |
| 実施者 | Claude(自動)|
| 実施日 | 2026-04-28 |
| 対象 | Qwen3 4B abliterated / Llama 3.2 3B abliterate / Dolphin 3.0 8B abliterated |
| 試行 | 各モデル 3 回、計 9 回 |
| 評価軸 | (1) JSON パース成功率、(2) 必須キー網羅率、(3) 値の妥当性、(4) 速度 |
| 結論 | ✅ **Llama 3.2 3B が JSON 品質+速度の両方でトップ**。Qwen3 4B は品質完璧だが speed ボトルネック(thinking 残存)。Dolphin 8B は **1/3 でキー欠落** が出て信頼性に問題 |

## 1. 動機

シミュレーションは [参考実装 agent.py](../10_共有資料/2d-multi-places-simulation-on-fire-public/agent.py) と同じく、エージェントごとに **JSON 形式で行動・記憶・理由を返させる** 設計([06_システム設計/04_エージェント設計/05_JSON_IO契約](../01_設計書/06_システム設計/04_エージェント設計/05_JSON_IO契約.md))。**JSON が壊れたら全行動が `stay` フォールバック** になり、創発観察が成立しない。3 モデルの JSON 信頼性を本番運用前に確認する。

## 2. 実行条件

### 2.1 プロンプト

`agent.py` の `create_decision_prompt` を踏襲し、日本語ペルソナ・状況描写を加えた版:

- system: `あなたは2D空間に生きるエージェントです。指示通り JSON のみで応答してください。他の文章は一切含めません。`
- user: 32歳東京会社員、近隣に 2 体、過去メモリ 2 件、受信メッセージ 1 件。出力は以下スキーマ。

```json
{
    "action": "move" or "stay",
    "direction": "up"|"down"|"left"|"right" or null,
    "memory": "...",
    "reasoning": "..."
}
```

完全なプロンプトは [json_test_logs/prompt_user.txt](json_test_logs/prompt_user.txt) / [prompt_system.txt](json_test_logs/prompt_system.txt)。

### 2.2 推論パラメータ

| パラメータ | 値 |
| --- | --- |
| temperature | 0.7 |
| num_predict | 1024 |
| num_ctx | 4096 |
| Qwen3 のみ user 末尾に | `/no_think`(thinking 抑制を期待) |

### 2.3 試行

各モデル 3 回、`/api/chat` 経由。生ログは [json_test_logs/results.jsonl](json_test_logs/results.jsonl) に保存(content / thinking / 速度すべて記録)。

## 3. 集計結果

### 3.1 信頼性指標(9 trial)

| モデル | JSON parse | 全キー揃う | action 妥当 | direction 妥当 | 平均時間 | 平均 tok/s |
| --- | --- | --- | --- | --- | --- | --- |
| Qwen3 4B abliterated | **3/3** ✅ | **3/3** ✅ | 3/3 | 3/3 | 11.3 s | 85.3 |
| Llama 3.2 3B abliterate | **3/3** ✅ | **3/3** ✅ | 3/3 | 3/3 | **2.4 s** | **120.2** |
| Dolphin 3.0 8B abliterated | **3/3** ✅ | **2/3** ⚠️ | 3/3 | 3/3 | 8.2 s | 11.7 |

→ JSON parse 自体は **9/9 成功**。差は **キー網羅性と速度** に出る。

### 3.2 token 内訳(thinking と content の分離)

| モデル | thinking_len | content_len | eval_count |
| --- | --- | --- | --- |
| Qwen3 4B(trial 1) | 2562 字 | 133 字 | 705 token |
| Qwen3 4B(trial 2) | 2769 字 | 130 字 | 755 token |
| Qwen3 4B(trial 3) | 3234 字 | 141 字 | 875 token |
| Llama 3.2 3B | **0 字** | 123-225 字 | 65-127 token |
| Dolphin 8B | **0 字** | 72-151 字 | 39-72 token |

> ⚠️ **重要発見**: Qwen3 に user 末尾で `/no_think` を付けても **thinking が抑制されなかった**(2500〜3200 字、トータル token の 75〜80% を占有)。`/no_think` の正しい指定方法は要再調査(system に入れる / 専用パラメータ / chat template の調整)。

## 4. モデル別の詳細

### 4.1 Qwen3 4B abliterated(★★★ JSON 品質完璧)

3 trial すべて構造的に完璧。日本語の memory / reasoning も自然で、シミュレーションの可読性も高い。

```json
// trial 1
{
    "action": "move",
    "direction": "right",
    "memory": "オフィスへ向かうための行動を取った",
    "reasoning": "エージェント2がオフィス内にいるため、近づく方向へ進む"
}

// trial 2
{
    "action": "stay",
    "direction": null,
    "memory": "オフィス内に進む必要がないと判断した",
    "reasoning": "エージェント2と挨拶した後、動きは必要ないと判断した"
}
```

**direction を `null` にする規則** も正しく守れている。

### 4.2 Llama 3.2 3B abliterate(★★★ 速度+JSON が最強)

3 trial すべて JSON 完璧。**応答時間は 0.7〜5.4 s、平均 2.4 s** と圧倒的。日本語は前回検証通り不器用("座りやすさ" "なるです" など)で、memory / reasoning の文がやや破綻気味だが、構造的には合格。

```json
// trial 2(0.7 s で完了)
{
  "action": "stay",
  "direction": null,
  "memory": "次ステップは、エージェント2と挨拶した後、席につくこと",
  "reasoning": "寒い気配があるので、座りやすさを選ぶ"
}
```

**100 人 × 100 ステップ = 10,000 呼出を 8 並列で回した場合の見積もり: 約 21 分**。性能バジェット([1 時間以内](../01_設計書/06_システム設計/08_バックエンド実装/04_並列実行と性能/01_性能バジェット.md))を圧倒的にクリア。

### 4.3 Dolphin 3.0 8B abliterated(⚠️ キー欠落 1/3)

3 trial 中 2 回は完璧、**1 回でキー欠落**:

```json
// trial 1 ✅
{
  "action": "move",
  "direction": "right",
  "memory": "エージェント3と会話したいので通路の方に行く。",
  "reasoning": "上司の存在が感じられ、指示や情報取得のチャンス"
}

// trial 3 ⚠️ direction と memory が欠落
{
  "action": "stay",
  "reasoning": "エージェント3と会話する準備をする前に、静かに待つことが最適。"
}
```

これは **本番で約 1/3 がスキーマ違反** ということ。10,000 呼出のうち 3,300 件が `direction`/`memory` 欠落 → 単純な辞書 `.get()` フォールバックで吸収できないと、解析・可視化で破綻する。

> 速度面でも 11.7 tok/s と最遅(8 並列でも約 1.7 時間/run)。**現状の Dolphin 8B は採用不可能** に近い。

## 5. 100 ステップ × 100 エージェント完走時間の試算

[性能バジェット](../01_設計書/06_システム設計/08_バックエンド実装/04_並列実行と性能/01_性能バジェット.md) の 1 呼出あたり所要時間 × 10,000 呼出 ÷ 並列度の単純試算:

| モデル | 1 呼出 (s) | 並列 8 で 10,000 呼出 | 目標(1 時間) |
| --- | --- | --- | --- |
| Qwen3 4B(thinking ON のまま) | 11.3 | **約 3.9 時間** | ❌ 大幅超過 |
| Qwen3 4B(thinking 完全 OFF できれば) | ~1.0 推定 | 約 21 分 | ◯ |
| Llama 3.2 3B | 2.4 | **約 50 分** | ✅ 余裕 |
| Dolphin 8B | 8.2 | 約 2.8 時間 | ❌ 超過 |

→ **Llama 3.2 3B が現状唯一「そのまま使えば 100×100 を 1 時間以内に完走できる」モデル**。

## 6. 設計判断への影響(改訂版)

### 6.1 採用方針(更新)

| シナリオ | 第 1 候補 | 理由 |
| --- | --- | --- |
| 小集団(2〜10 人)・品質重視 | **Qwen3 4B abliterated** | JSON 完璧 + 日本語自然。10〜30 ステップなら thinking 残存でも完走可 |
| 中集団(20〜30 人) | **Qwen3 4B abliterated** | 同上。100 呼出/ステップ × 30 = 3000 呼出なら 1 時間以内 |
| 大集団(100 人) | **Llama 3.2 3B abliterate(確定)** | JSON 完璧 + 圧倒的速度。日本語品質はトレードオフだが構造は守れる |
| Stretch 候補 | (Dolphin 8B は **保留**)| キー欠落率と速度が二重に問題。format schema 強制が動けば再評価 |

### 6.2 Qwen3 の `/no_think` 問題(残課題)

`/no_think` を user 末尾に付ける指示は **本検証では効かなかった**。要追加検証:

- [ ] system プロンプトに `/no_think` を入れる
- [ ] Ollama の `think` パラメータ(API 0.7+ で公式サポート予定)
- [ ] chat template の差し替え
- [ ] 実用上 thinking 込みの 2.8〜3 時間を許容するか

→ これが解決すれば Qwen3 4B も大集団に使える。

### 6.3 Dolphin の format 強制で救済できるか(残課題)

- [ ] Ollama API の `format: "json"` または `format: <JSON Schema>` を試す
- [ ] 強制で全キーが埋まれば採用候補に戻せる

## 7. 次に進めるべき検証

優先度順:

1. **Qwen3 の `/no_think` 正しい指定方法を見つける**(成功すれば Qwen3 大集団用に格上げ)
2. **Ollama の `format: schema` 強制で Dolphin のキー欠落を救済できるか確認**
3. Uncensored 度の評価(罵倒・反逆系プロンプトでの安全策残存度)— 次タスク
4. 実シミュレーションループでの 100 ステップ短縮版(20 ステップ × 10 体で約 2 分の小規模デモ)
