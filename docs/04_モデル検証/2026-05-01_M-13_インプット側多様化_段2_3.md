## 1. 背景

[M-12](2026-05-01_M-12_イベント途中発火と視覚化.md) で実走した `output/prod_v2_alien_5` 後半 Step 28〜30 に、全エージェントが同一文を循環させる **エコーループ** を観測:

```
step28 0→2: UFO の動向と小会議室 B のホワイトボードを同時に確認したいです。どうでしょうか?
step29 0→2: 同上(コピー)
step30 2→0: 同上 / 4→0: 同上 / 4→2: 同上 ...
```

`echo_max ≈ 1.0`(同一文レベル)。

一度はプロンプトで「直前文の 6 文字以上コピー禁止 + 自分の発話履歴と被るな」と**多様性を強制**する案(A+B)を入れたが、兵頭氏アドバイス「指示を書きすぎない」と反するため**撤回**。代わりに**インプット側を多様化する**方針へ転換([04_プロンプト構造 §4](../01_設計書/06_システム設計/04_エージェント設計/04_プロンプト構造.md))。

## 2. 段 2: personal_context 導入

### 2.1 設計

旧 `agents.conversation_profiles`(role / responsibility / speaking_style 直書き)を **legacy 化**し、新 `agents.personal_contexts`(生活の文脈)へ置換:

| 新キー | 内容 | 例 |
| --- | --- | --- |
| `family` | 家族構成・住まい | 「都内で一人暮らし。実家は地方」 |
| `hobby` | 趣味 | 「週末は街歩きでカメラを持ち歩く」 |
| `today_mood` | 今日の気分・体調 | 「風邪気味で少し集中力が落ちている」 |
| `recent_concern` | 最近気にしていること | 「親の体調と通院の付き添い」 |
| `expertise_hint` | 何となく詳しい分野(役職ではなく経験ベース) | 「学生時代に天文同好会で星を見ていた」 |

**役職名・speaking_style・責務記述は入れない**(役割を演じさせる設計に戻ってしまうため)。

実装:[src/simulation.py:_personal_context_to_prompt](../../src/simulation.py)。`personal_contexts` 優先、未設定なら legacy `conversation_profiles` で警告ログ。

### 2.2 ラン結果(`output/seg2_check_alien_5/`)

5 体 × 30 step、所要 約 32 分。

#### 前半(Step 1〜2)で出た発話 — 個別性が明確に滲む

| Agent | personal_context | 発話 |
| --- | --- | --- |
| 1 | 朝から焦り、会議立て込み | **「今朝から会議が続いていて、少し焦っています」** |
| 2 | 風邪気味、集中力低下 | **「給湯コーナーで紅茶を飲んで少し休憩してもいいですか?」** |
| 3 | 新婚・最近マンション購入・近所のジム | **「最近、マンションを買ったんですけど、近所のジムはまだ利用してないですね?」** |

prod_v2(役割直書き)では「ここはオフィスフロアで…」のような没個性の出だしだったのと比べ、**LLM が「自分の生活」として話している**ことが視認できる。

#### 後半(Step 28〜30)— エコーループは依然残存

```
step28 0→2: UFO の形状や光の変化について詳しく教えていただけますか?今、その様子を確認したいと思っています。
step29 0→2: UFO の形状変化の原因について詳しく教えていただけますか?また、その変化がどのように起こっているのか知りたいです。
step30 0→2: 同上 / 2→0: 同上 / 4→0: 同上 / 4→2: 同上
```

→ **段 2 単体ではエコーが完全には消えない**。原因仮説:イベント発火後、全員に同じ prompt_text(「UFO は座標 (-15, 12) 付近を移動中」)が入るため、後半 memory が同じ語彙で埋まり personal_context の効果が薄れる。

## 3. 段 3: イベント観察非対称化

### 3.1 設計

`AlienEvent.perceived_info(agent_position)` を **距離依存** に変更([src/events/alien.py](../../src/events/alien.py)、要件定義 [02_エージェント属性 §6.5](../01_設計書/01_要件定義/03_機能要件/02_エージェント属性.md)):

| 距離帯 | 既定閾値 | 知覚内容 |
| --- | --- | --- |
| **Near** | 距離 ≤ `near_radius` (8.0) | 「目の前に UFO がいる。座標 (X, Y) でほぼ静止して見える」 |
| **Mid** | < 距離 ≤ `visible_radius` (18.0) | 「遠くに UFO らしきものが見える。座標 (X, Y) 付近」 |
| **Far** | 距離 > `visible_radius` | `perceived_info=None`(直接観察不可)。会話伝播でのみ知る |

### 3.2 ラン結果(`output/seg3_check_alien_5/`)

5 体 × 30 step、所要 約 27 分。**Step 15〜17 で発話分離が明確に観察された**:

| step | from→to | 発話 | 解釈 |
| --- | --- | --- | --- |
| 15 | 1→2 | 「**UFO が見えると聞きました**。本当に遠くにありますか?」 | ← 伝聞経由(直接視認していない人) |
| 16 | 1→2 | 「**UFO が見えるというので**、その位置を確認するために少し下に動くことにしました」 | ← 伝聞 → 確認行動 |
| 16 | 2→1 | 「**UFOが見えると聞き**、どうしてその場所にいるのか確認したいです」 | ← 伝聞 → 詳細追求 |
| 17 | 2→1 | 「**体調が悪い**ので、少し動こうと思っています。**UFOが見える**ので、その場所に近づきたい」 | ← Mid 視認 + personal_context(体調)の **複数軸合成** |
| 17 | 3→2 | 「**UFOを見たのですか?** その場所はmain_officeですか?」 | ← Far にいて、見た人に確認 |

prod_v2 / seg2 では絶対に出なかった「**聞きました**」「**見たのですか?**」という伝聞・確認の発話が出現。**段 3 が狙ったとおり知覚の分離が会話に反映された**。

### 3.3 観察された創発の兆し(Step 17 の合成発話)

> 「体調が悪いので、少し動こうと思っています。UFOが見えるので、その場所に近づきたい」

これは **個別性(体調)× 知覚(Mid)× 行動(近づく)の 3 軸が合成された発話**で、prod_v2 / seg2 では出なかった質。「ルールでは書けない創発」(兵頭氏フレームワーク)に最も近づいた瞬間。

### 3.4 副作用 — 後半メッセージ枯渇

`events.jsonl` の `place_change` を見ると、UFO 観察に向かうエージェントが main_office から離脱:

| step | 出来事 |
| --- | --- |
| 1 | Agent 0 が main_office を離脱、フィールド端 (25, -7) に張り付く |
| 16〜30 | Agent 0 が境界クランプを繰り返す |
| 27 | Agent 1, 3 も main_office を離脱 |
| 29 | Agent 2 も離脱 |

結果、Step 26 以降は全員が `current_place=None` で散開し、`current_place != current_place` 縛りで通信不能。Step 26〜30 のメッセージ数は 0。

→ **後半のエコーが緩和されたかどうかは、5 体小集団では検証不能**。エージェント密度が高い大集団(粉川氏 34B × 100 体)で再検証する必要がある。

## 5. 副次的な修正

### 5.1 `event_activated` を `events.jsonl` に記録

[M-12 prod_v2 ラン](2026-05-01_M-12_イベント途中発火と視覚化.md) の `events.jsonl` に alien イベント発火が記録されていなかった([src/simulation.py](../../src/simulation.py) で `logger.info` のみで step_events に追加していなかった)。M-13 着手と同時に修正:

```json
{"step":15,"type":"event_activated","kind":"alien","name":"alien_0",
 "prompt_text":"...","position":[-15,12]}
```

`tools/analyze_run.py` の `event_counts` で集計可能になり、創発指標の計測根拠が揃った。

### 5.2 `conversation_profiles` を legacy 扱いに

`personal_contexts` と両方指定した場合は `personal_contexts` を優先し、警告ログを出す。`scenario_alien_5.yaml` は新スキーマに移行済み。

## 6. 残課題と次の手

1. **大集団(100 体)でのエコー検証**は私側 4B では物理的制約で困難 → 粉川氏 34B × 100 体ランへ引き継ぎ。`personal_contexts` が 100 件必要(LLM 生成で半自動化が現実的)
2. **エージェントの場外滞在**: 段 3 で UFO 観察に向かったエージェントが場所外に出ると通信不能になる物理は設計通りだが、観察品質を考えると将来的に「フィールドのどこにいても近傍 N 人とは話せる」緩和案も検討余地あり
3. **複数イベントの同時発火**: 段 3 の知覚距離帯は AlienEvent のみ実装。`ZeroGravityEvent` も同様の対応が必要(ただし無重力は局所現象ではなく全体現象なので spec 検討から)
