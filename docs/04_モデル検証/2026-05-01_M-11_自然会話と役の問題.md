# M-11: 自然会話と「役を演じさせない」設計判断

> 2026-05-01 の検討記録。Codex(別 AI エージェント)から提案された
> `conversation_profiles`(役割ベースのペルソナ拡張)を一部受け入れたが、
> 「役を演じる機械的会話」になる懸念が出たため、**`personal_context`
> (生活の文脈ベース)** に再設計する判断に至った経緯を残す。

---

## 1. 背景: prod_v2_alien_5 で起きていたこと

[output/prod_v2_alien_5/messages.jsonl](../../output/prod_v2_alien_5/messages.jsonl)
の前半(step 1〜12)は、5 体全員が「静けさ」「春の風」「光」「静かな心」
を反復し、step 15 のイベント発火後は全員が「驚き」を 1 単語連呼する
モード崩壊状態だった。

ステージ B(MBTI ペルソナ刷新)で `reflection_mean` を 21 倍改善した経緯が
あるにもかかわらず、12 step で再び同質化が観測された。

ユーザの違和感:**「自然な会話」になっていない、機械的すぎる**。

---

## 2. Codex(別 AI エージェント)による診断と処方箋

### 診断(おおむね妥当)

1. **会話の目的がない** — 仕事・役割・関心・目的がほぼなく、LLM が
   何を話せばいいか分からず抽象語に逃げる
2. **ペルソナが会話を生む情報ではない** — `age/gender/nationality/mbti`
   は差分にはなるが「何を気にしているか・知っているか・したいか」が弱い
3. **プロンプトが一時期抽象化されすぎていた** — 「今、頭に浮かんだ一言」
   は独白を誘発(これは 4/30 改訂で対処済)

### 処方箋

- A. Agent に軽い役割を戻す(観察役 / 慎重な人 / 記録する人 …)
- B. 各 Agent に個別の目的を持たせる
- C. イベント後の情報を全員同じにしない(情報の非対称化)
- D. メッセージプロンプトを「独白」ではなく「相手への発話」に固定
- E. `llm_io.jsonl` に実際のフルプロンプトを保存

---

## 3. 本プロジェクトの判断

### 採用するもの

| Codex 提案 | 採否 | 理由 |
| --- | --- | --- |
| C. 情報の非対称化 | ★ 強く採用 | 3 階層(物理)層の真価。エコー対策の根本 |
| D. 相手への発話に固定 | ✓ 既に実装済 | agent.py の `has_active_event` 分岐 |
| E. `llm_io.jsonl` ログ | ★ 強く採用 | 観察可能性。提出物の根拠にも |
| B. 個別の目的 | △ 採用するが形を変える | 後述 |

### 棄却するもの

| Codex 提案 | 採否 | 理由 |
| --- | --- | --- |
| A. 役割を戻す(観察役 / 記録係 …) | ✗ 棄却 | **4/29 議事録 §4** で「役職・職業はあえて与えない、自然発生を観察するため」と明示的に外した方針と直接矛盾する |

### 一度試して撤回するもの: `conversation_profiles`

2026-05-01 中に Codex 提案を素直に実装した
[config/scenario_alien_5.yaml](../../config/scenario_alien_5.yaml) の
`conversation_profiles` セクションは、結果として **演劇の配役表** に
なっていた:

```yaml
- role: "当日の進行役"
  responsibility: "オフィス内の状況を整理し..."
  speaking_style: "短く落ち着いた口調。相手に確認する"
```

問題点:

1. **役を演じるモードに入る** — 「進行役」と書かれた agent は
   進行役を全うしようとして喋り、自然発生を観察できない
2. **`speaking_style` が MBTI を打ち消す** — 「短く落ち着いた口調」と
   書かれると、MBTI が ESFP(陽気・活発)でも落ち着いた口調になる
3. **4/29 議事録の「役を与えない」方針と衝突** — F-4 ルール違反になる

---

## 4. 採用する設計: `personal_context`(生活の文脈)

「役」ではなく「**今日のその人の文脈**」だけを与える。スキーマ案:

```yaml
personal_context:
  - mood: "昨日寝るのが遅くて少しぼーっとしている"
    on_mind: "金曜のプレゼン準備が終わっていない"
    today: "コーヒーを淹れに席を立とうとしていた"
  - mood: "朝、子どもが熱を出して保育園を休ませた。気もそぞろ"
    on_mind: "妻からの連絡待ち"
    today: "メールを片付けようとしていた"
  - mood: "出社前にジムに行ったので体は元気"
    on_mind: "週末の旅行の予定"
    today: "同僚と昼ごはんの相談をしようとしていた"
  - mood: "特に何もない、いつも通り"
    on_mind: "年末調整の書類どこに置いたっけ"
    today: "デスクで資料を読んでいた"
  - mood: "新しい本を読み終えた直後で頭が冴えている"
    on_mind: "読んだ内容を誰かと話したい気分"
    today: "ホワイトボードに何か書こうとしていた"
```

設計ポイント:

- **`role` がない** → 役を演じない
- **`responsibility` がない** → 義務感がない
- **`speaking_style` がない** → 話し方は MBTI に任せる
- **`mood` / `on_mind` / `today`** → 生活の文脈、内面の状態
- **イベントと無関係な悩みを混ぜる** → 全員が即座にイベントに
  集中して同じ反応をしない(意識の自然な分散)

期待される効果:

- 宇宙人が来ても agent 1(子ども熱)は「保育園からの連絡を確認したい」
  と動くかもしれない
- agent 2(旅行の予定)は「週末の便、大丈夫かな」と漏らすかもしれない
- 役を演じるロボット会話ではなく、**人間の意識のリアリスティックな分散**

---

## 5. プロンプト側の追加調整(機械っぽさを下げる)

| 項目 | 現状 | 改訂案 |
| --- | --- | --- |
| 発話強制 | 毎ステップ「相手に向けて 1〜2 文で話してください」 | 沈黙(`message: ""`)を許可 |
| 発話必須項目 | 「質問・確認・提案・具体的観察のいずれかを含める」 | 必須から外す。人は「うん」「へえ」「まあ…」とも言う |
| `speaking_style` 注入 | あり(conversation_profiles 経由) | **削除**。MBTI に書き分けを委ねる |

## 7. 学び

- 「役を与えるべきか」は、**研究目的(自然発生を観察)** と
  **会話の自然さ** のトレードオフ。Codex の処方箋は後者を最大化する
  方向だが、本プロジェクトは前者を優先する設計
- 「自然な会話」は **役職ではなく生活の文脈** から生まれる。
  オフィスにいる 5 人は、誰も「進行役」と任命されていないが、
  各自が抱えている事情が会話の駆動力になっている
- LLM に与える情報は **「演じさせる脚本」** ではなく
  **「内面状態のスケッチ」** であるべき(粉川氏「指示を書きすぎない」)
