## 2. 実行内容

### 2.1 起動

```powershell
(.venv) PS D:\Projects\IRIS-company\departments\r_and_d\singulab> ollama run huihui_ai/dolphin3-abliterated:8b-llama3.1-q4_K_M
```

### 2.2 入力プロンプト

system **未設定**(モデル既定のまま)。`num_gpu` も **未指定**(Ollama 0.21 が自動でレイヤー配分)。
user 入力は **2 行構成**(改行を `... 日本語で書くこと` で続けて指定):

```
あなたは東京の大企業で働く32歳の会社員です。景気が悪い中、今日のあなたの気分を独白として教えてください。
日本語で書くこと
```

> ※ 補足: 最初は `>>> /set parameter num_gpu 20` とコマンド行をコピペした際、`>>>` まで含めて入力してしまい、モデルが普通の質問として英語で長文解説を返した。`>>>` は REPL のプロンプト表示記号なのでコマンドには含めない。
>
> 副次効果として、Ollama 0.21 は **明示的な `num_gpu` 指定なしでも自動でレイヤーを GPU/CPU に振り分ける** ため、`num_gpu=20` を設定しなくても動作することが分かった。

| 観点 | C-06 観測 | 本確認 | 解釈 |

## 5. 設計判断への影響

### 5.1 採用方針(改訂案)

| シナリオ | 第 1 候補 | 第 2 候補 | 備考 |
| --- | --- | --- | --- |
| 小集団(2〜10 人) | Qwen3 4B abliterated | Dolphin 8B abliterated | 品質重視。Dolphin は速度 1/4〜1/5 だが品質は十分 |
| 中集団(20〜30 人) | Qwen3 4B abliterated | Llama 3.2 3B abliterate | 速度と品質のバランス |
| 大集団(100 人) | Llama 3.2 3B abliterate | Qwen3 4B abliterated(`/no_think` 必須) | 完走時間を重視 |

→ Dolphin 8B は **stretch というより「品質重視シナリオの第 2 候補」** に格上げできる。ただし速度ボトルネックで大集団用としては不適。

### 5.2 Dolphin 採用時の運用上の注意

- **system プロンプトで「独白」「口語」「短く」を明示する必要あり**(放置すると論文調・長文化する)
- **Uncensored 度合いの確認は別途必要**([2026-04-28_dolphin3_uncensored評価.md](.) を別途実施推奨)
- **Ollama 0.21 では `num_gpu` 未指定でも動作**。明示するなら 20 前後

### 5.3 残課題

- [ ] system プロンプトで長さ・口語化を制約した場合の品質確認
- [ ] **Uncensored 評価**(罵倒・反逆系のプロンプトで Safety が外れているか)
- [ ] JSON 出力形式での品質確認(`{"action": ..., "memory": ...}` を返せるか)
- [ ] 100 ステップ × 8B = 8〜13 分/エージェント。100 体なら 13〜22 時間 → **大集団には不向き** を再確認
